# Excel 計算規則與可追溯來源

## 1. 規則權威與遷移原則

依 review r2 記錄的使用者確認，ERP 改版後「標籤」才是優惠標記權威欄位；目前人工把標籤貼到備註供舊公式讀取。本次檔案尚未套用 workaround，其快取不是正式業務正確答案。初版 P1 預設 `erp-tag-v1`；目前正式目標版本為 `erp-tag-v4`。`excel-v260922-compat` 的公式／欄位讀取規則僅保留作歷史版本解讀，不可啟用為現行正式開單依據。5 天是週一到週五；天數為收費級距；寫功課不列入折扣；美安是歷史班型。

> **#159 PR-1 diagnostics contract (historical; superseded by PR-2 below):** PR-1 stopped compat/shadow-v2 and new diagnostics snapshots while preserving raw historic issues and UI actionable projection. PR-2 additionally fixes every new calculation to v4 and removes old calculator paths. The remaining §9.7 dual-track material is historical design, not current runtime behavior.

> **#159 PR-2 現行計算入口：** 新 Run 與新計算預覽只允許 `erp-tag-v4`。active 任一非 v4 舊 Run（含 v1／v2／v3、compat 或未知版本）不會透過一般 activate／recalculate／apply 偷偷沿用舊版本或轉成 v4；使用者須在設定頁明確選取升級 v4。升級預覽的 `before` 讀取舊 Run 已保存的結果，`after` 才以 v4 計算；舊 Run 與其計算值、issues、settings/category snapshot 均不重算或回填。下方 v1／v2／v3／compat 公式和版本差異只描述歷史結果或舊 run 的只讀呈現，不代表產品仍提供舊版計算入口。詳見 [03 §5.6](03-architecture-api.md) 與 [06 D57](06-handoff-decisions.md)。

輸出帶 ruleSetVersion 與 numericPolicy。來源欄位修正、名單修正與數值邊界差異分別記錄，不混成相容誤差。

原本 D 僅直接使用 A/B/C/F/I；本工具另外要求人員代碼，是避免同名與列序異動造成錯配的產品設計。對舊格式無代碼的檔案顯示不支援與原因，不偷偷退回姓名主鍵。文字欄位維持字元級完全一致，非文字欄位（如 Date 型、數值）採正規化等價。

以標頭匹配而非字母座標。預設前 20 列辨識唯一一列完整必要標頭；若沒有或有多列候選，要求選擇／修正。標頭做 BOM 去除、前後空白與換行整理；正規化後重複的必要標頭視為錯誤。未知多餘欄可忽略且列於預覽。別名只接受已明確設定的映射，不以模糊相似度自動決定。

讀取所有儲存列／欄，包括 Excel 隱藏與篩選掉的列欄。隱藏不是業務上排除。完全空白列跳過；非空但缺識別值的列報錯。字串保留原文與清理後值；班名／姓名只適度去頭尾空白，不全域刪標點、年度或中間空白。

學生表只讀儲存值，必要資料欄若含公式，P1 拒絕該檔並提示重新匯出；不在伺服器執行任意上傳公式。Excel 原生 sharedStrings／inlineStr 都須讀得出。第一版只接受未加密 `.xlsx`，不接受 `.xls`、`.xlsm`、CSV 或密碼檔。

## 3. 班名辨識：原文、顯示、計算鍵分離

RAW B 欄一學生可有多個換行分隔班級，如 `115國小數學-三A[團]`、`兒童美語-EA[團][Starter]`。每個 token 保留原序、原文；所屬班級全文在前端與 API 按需要由 `student_enrollments` 逐筆依 `token_index` 升冪以換行符重組還原呈現，不重複增設 class_text_raw 欄位。顯示用 classId 對應，不把全部方括號刪掉。

相容計算抽取方式必須保留：D E/F 只從整段 B 文字找第一個 `國小數學-` 與第一個 `兒童美語-`，各截到其後第一個 `[團]`（含 `[團]`）。數學前綴年度自然不在截取結果裡；美語後面的級別也不在結果裡。兩種各至多一班參與天數扣除。同類報兩班時提示「舊版只取第一班」，不直接改成全部相加。

**R17：同類別重複報名提示（D19，v2 行為；v3 見 §9）。** 對每個學生，按類別（`兒童美語`／`國小數學`／一般`國小輔導`／`寫功課`）統計 enrollment 筆數，凡某類別 >1 即產生 `DUPLICATE_SUBJECT_ENROLLMENT`，列出該類別全部原始 token 與各自的 ERP 登記級距。**這是純提示，不改任何計算值**：數學／美語扣天仍各只取第一班，科數仍依 R09（含寫功課扣 1）。先將寫功課分類，再判一般國小輔導，同一 token 不同時計入兩類；一般輔導＋寫功課各一筆不觸發 R17，但仍保留 U20 的混合情境提示。每名學生每個重複類別產生一筆 issue，附全部 enrollmentIds；提示學生數以 personCode 去重，不是 issue 筆數。美語／數學的 ERP 級距標 not_applicable，不推算天數後綴。

提示範圍**必須包含一般國小輔導**。數學／美語的重複至少還會透過「只取第一班」影響天數而留下線索，但國小輔導的重複目前**完全沒有任何訊號**——R09 算類別存在性故兩筆仍是 1 科，R11/R12 只查數學／美語抽取鍵故天數也不受影響。樣本中兩種情形各 1 人：列 43（`國小輔導-三年級[團]` 與 `國小輔導-三年級[團][4]` 並存，同一人不可能同時是 5 天與 4 天級距）、列 52（`兒童美語-EG` 與 `兒童美語-EA`，兩班課輔扣天皆為 1，只有 EG 計入）。

依 D17，這類情形不在公式內修正，實際開單由人工處理；工具的職責是讓對帳者看得見，以便回頭檢查 ERP 輸入是否有誤。安親或課輔的判定依學生年級而非班級（見 §7），即使同時被加入兩班國小輔導也不改變這一點。

正式版也維持第一個數學／美語的選取順序；排課鍵優先使用該enrollment在本run已核准的映射，尚未核准時只允許legacy抽取鍵與seed排課班名精確相等查找。找不到即fallback＋問題，不做模糊匹配。正式名單依classId，legacy抽取鍵僅維持天數算法與初始seed對照，不反過來决定名單。人工alias變更的計算影響須經預覽，舊compat診斷仍依原抽取鍵。

UI 班級辨識與此算法不同：完整報名 token → 明確別名 → classId。可預覽建議對應，但衝突必須手動指定。新班可正常列名單；未設定排課的班不能自動宣稱沒有衝堂。

同名不同年度、分校或級別可能不同班；classId 是內部識別，名稱不是主鍵。若不同 ERP token 對應同一班，每班人數按學生去重，但仍保留所有原始 token 與異常提示。

### 3.1 結構化班名與名單政策

`115國小輔導-四年級A[團][4_5] (2026-10-01離班)` 解析成 yearPrefix=`115`、baseName=`國小輔導-四年級A`、groupFlag=`團`、modifiers=`["4_5"]`、withdrawalDate=`2026-10-01`，rawToken 完整保留。只解析已知文法，未知／矛盾修飾為 parseStatus=needs_review。

一般安親／課輔的已知級距修飾不是班級身份，同一年度／範圍／baseName 的不同級距進同班，級距保留在 enrollment。美語 [W1]／[Starter] 等修飾保留在候選身份，是否同班由明確映射決定。年度不得全域刪除；無年度排課 seed 對 ERP 年度的映射必須預覽確認，解析不等於批准 alias。多分校字串不自動複製 enrollment。

無 A/B 表示當時只有單一班，不能單憑文法推定現在的一A班。D18 已確認本次數學一班與一A為同班，應提出具名候選、經設定頁確認才建立映射。禁止把 `國小數學-一[團]` 自動對一A，或合併四年級 A/B。尚未映射的 token 仍有可搜尋的待設定名單與去重人數，不得消失。

舊名單為大小寫敏感 FIND(工作表名, 班級全文) 子字串搜尋，源於 Excel 命名限制，已知 `國小輔導-四年級` 會抓到 A/B。新名單以結構化 token 的明確映射／classId 相等選取；parity 驗收要求逐筆解釋差異，不要求重現碰撞。

### 3.2 ERP 登記級距與離班標記（P1）

只對已識別的一般安親／課輔 enrollment 解讀 `[3]`、`[3_5]`、`[4]`、`[4_5]`、`[5]` 為 3、3.5、4、4.5、5；無後綴且無未知修飾時預設5。寫功課／美安不套一般級距預設；未知後綴不可當無後綴回5，美語／數學修飾不是天數。

保存 erpBillingTierRaw（無後綴 null）、erpBillingTier、tierParseStatus，**不餵回天數計算**。每個 enrollment 有 tierComparison={computed,erpDeclared,status,issues}，status 為 match／mismatch／not_applicable／unavailable。缺排課仍有 fallback 時可比較數字，但同時 needs_review；match 不代表資料完整或帳單正確。未知年級、解析失敗、無計算值為 unavailable。多 enrollment 不壓成單一學生級距。

固定原檔、原排課、不新增別名、erp-tag-v1 下，179個一般輔導 tokens（141有級距、38無後綴）預期174 match、5 mismatch。來源列30：5→4.5、35：4.5→4、43：5→4、51：4.5→4、52：5→4。此為初始fixture預期，設定改變後不能硬湊5筆；mismatch 不表示必為ERP錯誤。

僅解析 token 尾端明確 `(YYYY-MM-DD離班)`，依使用者確認**不排除**、不改科數／扣天。樣本34人、37 tokens。顯示「離班標記：日期」，不一律稱「已退班」（可能是未來日）。學生檔沒有完整入班／異動歷史，不能重建任意日期真實名單。

## 4. 每週時段與扣除天數

### R01：時段時長與重疊

來源 S!C1:D2、F4:J96。初始安親 13:00–16:00，課輔 16:30–19:30。時間在引擎中以本地一天內整數分鐘表示，不使用 UTC 日期換算。

`duration = end - start`

`overlap = max(0, min(end, windowEnd) - max(start, windowStart))`

首尾恰好相接重疊為 0；完整包覆取窗口長度。

**規則版本差異（D30 衝堂同星期規則）**：
- **`erp-tag-v1` 與 `excel-v260922-compat`（歷史凍結）**：S 原公式逐列只看時刻，不檢查星期；星期文字僅用於顯示。週六設定也被算入 S 的重疊結果。相容版保留此行為，舊 run 結果位元不可變。
- **`erp-tag-v2`（正式，D30 Operator 拍板）**：科目時段只跟同星期的安親／課輔窗口比衝堂；安親／課輔為一～五的課，星期六的課自然重疊為 0。星期、起、迄三欄是一組有關係的資料，應共同決定衝堂。若科目時段星期不在窗口星期集合內（如週六、週日），重疊分鐘數自然為 0。
- **未知星期處理（F3/K2，選定方案 (a) 皆 fail-closed）**：v2 同星期路徑下，時段星期缺失（null／空）或無法識別（非法自由文字）一律視為未知，該時段衝堂計為 0，並出 `UNKNOWN_WEEKDAY` 告警＋`tierComparisons` 標 `SCHEDULE_INCOMPLETE`（needs_review），不靜默歸零、不靜默照舊。v1/compat 不檢查星期，行為凍結不變。

同日兩課時間重疊也照每列相加，原本不是 union 合併。禁止在重寫時自行去重重疊分鐘。時段重複可警告，但不得默默刪除。

### R02：每堂轉成負扣天

- 安親 `rawAnqin = -overlapAnqin / 180`。
- 課輔若 `overlapTutoring >= 120` 且 `end > 18:30` 且 `end < 19:30`，`rawTutoring = -1`；否則 `-overlapTutoring / 180`。

18:30 與19:30 是嚴格邊界。業務意義（使用者 2026-09-23 確認，D24）：約 2 小時、落在課輔時段中間的課（如 16:50–18:50、17:00–19:00），下課後學生不再進課輔班，故當天算扣滿 1 天；貼齊課輔頭尾的 16:30–18:30、17:30–19:30 則照比例計算（各 120/180）。**DIFF-01：正式整數分鐘策略不是與 Excel 日分數浮點完全等價的改寫**，>=120 和 MOD 的0.3／0.8邊界可能不同。診斷路徑保留日分數、原運算順序與 raw 值，不用全域 epsilon 掩蓋。**但比較運算不可用 IEEE754 逐位元比較冒充 Excel**：使用者 2026-09-23 原生實測 17:00–19:00 的重疊（儲存值 119.99999999999989）在 Excel 判 `>=120` 成立，逐位元比較則不成立；MOD 的單堂邊界（36／126 分）亦被吸收，但同班兩堂各 18 分鐘加總後的誤差未被吸收：精確取整 0、Excel 取整 -0.5。DIFF-01 因此確實存在，發生在同班多堂加總；四例原生錨點與比較模型見 04 §3 DIFF-01 段。現有樣本一致不代表未來時段必然一致；#161 時期曾將實際差異標為 NUMERIC_POLICY_DIFFERENCE 並展示兩值。#159 PR-1 起新 run 不再呼叫該比較或產生此 warning；此差異模型留作歷史數值政策記錄，不可據此把新 run 標成已確認無問題。

原公式除数固定 3 小時，即使 C1:D2 的窗口改長短也不自動改除數。P1 把 `minutesPerBillingDay=180` 作規則參數，與可改時間窗分開。不能認為窗口長度就是除數。

### R03：先每班相加，再取整

來源 C!B4:E57，SUMIF 引用 S!A4:A96 與 H/J。兩個 ruleSet 都先把同一班全部時段的扣天相加（課輔特例的整日 1 也一併相加），**不得逐堂先取整**；差別只在取整規則。

**erp-tag-v1（正式，D24）**：對扣天量 `d = -x ≥ 0` 取整，門檻作用在 d 的小數部分：

```
n = floor(d)
f = d - n                          // 0 <= f < 1，以有理數比較
roundedDeduction = n + (f < zeroBelow ? 0 : f < fullAtOrAbove ? 0.5 : 1)
rounded = -roundedDeduction
```

`zeroBelow=0.3`、`fullAtOrAbove=0.8` 與 `minutesPerBillingDay=180`、課輔整日特例（重疊 ≥120 分鐘且 18:30 < 下課 < 19:30 計 1 天）同為 ruleSet 參數，集中定義、不散落程式碼。調整任一參數即建立新 ruleSetVersion，先預覽受影響學生再啟用，舊 run 保留原版本結果。P1 參數由程式定義，不做參數編輯畫面，也不建任意公式或規則 DSL。

**excel-v260922-compat（診斷）**：保留原公式對負數取整：

```
n = floor(x)                       // Excel INT，負數向負無限方向
f = x - floor(x)                   // Excel MOD(x, 1)，0 <= f < 1
rounded = n + (f < 0.3 ? 0 : f < 0.8 ? 0.5 : 1)
```

原公式還分 `f < 0.5`，兩側回傳都是0.5，所以在相同 x/f 輸入下合併分支等價；此結論不延伸至更換 x/f 數值策略。因 MOD 作用在負數，換算成扣天量後實際門檻變為「≤0.2 不扣、0.2–0.7 扣 0.5、>0.7 扣 1」，與使用者確認的業務規則不同（D24）。

## 6. 折扣科數與基本折扣

### R09：已補科數（v2 行為；v3 見 §9）

來源 D!I2。對整段所屬班級字串，各計一次是否含 `國小輔導`、`國小數學`、`兒童美語`，得到 k（0–3）。不是報名班級筆數。

班級空白：科數 null。若 k>0，結果 `k - (含寫功課 ? 1 : 0)`；否則 0。例：寫功課＋數學＋美語，k=3，結果 2；同類兩個美語班仍算 1 科。

這是原公式對「寫功課不列入折扣」的實現方式。若同一學生同時有一般國小輔導與寫功課，原公式仍減 1；若寫功課班名不含國小輔導也可能減到別類科數。這類混合輸入先警告並維持相容，未取得業務決策不得自行改成逐 enrollment 計數。

### R10：基本折扣

來源 D!H2。特殊折扣有值時直接覆蓋一般規則，不相乘、不取更優惠值。否則 `effectiveCount = subjectCount + (sibling ? 1 : 0)`：大於 2 為 0.9，等於 2 為 0.95，其他為 1。

姓名空白：原公式空白；匯入規格會更早報錯。無班級的 93 筆歷史 H 快取原為空白；依 operator 2026-10-03 裁決（d-20261002160111112854-66），無報名（科數 null）學生的合計折扣預設為 10000（無折扣），科數仍維持 null，刻意與原 Excel 樣本分歧（開發階段每次測試前清 DB 重匯，不考慮舊 run）。若無班級但有特殊折扣標記，特殊折扣優先。

折扣內部用整數 basis points：10000=1、9500=0.95、9000=0.9、8500=0.85、8000=0.8、7000=0.7。UI 可顯示 95%（95 折），不能顯示「折扣金額 95%」。API 對 null、10000 必須分別表示。

## 7. 安親／課輔每週收費天數

來源 D!E2/F2。設 ma、en 是 R03 得到的第一個數學／美語班扣天（皆為負值）；找不到時原公式以 0 替代。extra 為 R05，空值視為 0。

### R11：安親（v2 行為；v3 見 §9）

僅年級小一／小二進入計算，其他原顯示「非安親」。

`days = max(3.5, 5 + maAnqin + enAnqin - extra, has寫功課Or美安 ? 5 : 0)`

注意：寫功課／美安判斷在 v2 與 compat 軌是 MAX 的第三個參數，不是單純錯誤時的備援。因此存在此字樣時結果至少 5，即使有額外扣天也會被壓回 5。若 extra 有值，原輸出還會附 `*額`，例如 `5*額`。API 把 days 數值與 extra 標記分開，UI 可保留對照顯示。（v3 正式軌修正見 §9.4 與 D51：固定 5 天在額外扣天前套用，額外扣天扣在固定 5 天之後，但受年級下限 3.5 保底）。

### R12：課輔（v2 行為；v3 見 §9）

僅小三／小四／小五／小六適用，其他原顯示「非課輔」。

`days = max(3, 5 + maTutoring + enTutoring - extra, has寫功課 ? 5 : 0)`

extra 標記相同。（v3 正式軌修正見 §9.4 與 D51：固定 5 天在額外扣天前套用，額外扣天扣在固定 5 天之後，但受年級下限 3.0 保底）。原公式依年級即可產生天數，即使學生未報安親／課輔。產品因此要區分：`legacyGradeBasedDays`（Excel 總表值）與 `isEnrolledInCareClass`（有無實際報名）；未報該課不把其級距當作應開項目。

年級未知與已知非適用分開：未知回 `unavailable`，不是「非安親／非課輔」。沒有排課命中時同時保存 `legacyFallbackDays` 與問題，不把 fallback 當已確認結果。UI 可以展示「Excel 相容值 5；排課缺漏待確認」。

年級「無」、null、空字串皆未知；樣本第22列為「無」，正式結果 unavailable，舊版顯示另留診斷。排課完整性根據 ScheduleSession：schedule_not_found＝無設定；schedule_empty＝一般科目有班名但無有效時段；no_overlap＝有有效時段且無交集。前兩者保留0扣天fallback並 needs_review，後者 calculated。部分時段缺起／迄標 schedule_incomplete，不能略過殘缺列。安親／課輔本班以 scheduleSource=care_window 使用共用窗口，不因無session報錯。

原seed有49班：40有時段、8安親／課輔共用窗口、1個 `國小數學-一B[團]` schedule_empty。13人抽取的 `國小數學-一[團]` schedule_not_found，禁止自動對一A。人工預覽若套一A，13人安親各少0.5天、179筆級距mismatch從5增至18，必須先呈現後果再由人員決定；吻合率不是排課正確性的證明。

先各班取整再學生相加、最後扣額外天數並套下限；不得把所有時段合併取整或先扣 extra 再取整。此算法是每週收費級距，不乘月份天數、不自動扣國定假日。

## 8. 課程情境的最終折扣

**優先序（#124 operator 裁示）**：**特殊折扣優先於「寫功課固定 100%」**。R07／R10 的特殊折扣先於本節的寫功課規則套用；學生自帶的特殊折扣標籤不被寫功課的 100% 覆蓋掉。此優先序在原始 Excel 座標的敘述中未載明，是業務裁決補上的，明寫於此以免下一位讀者誤以為是回歸。診斷軌 `excel-v260922-compat` **不**套用此優先序（刻意保留原 Excel 公式，只供比對與診斷；見根 CLAUDE.md §2 雙軌制度）。

裁示的邊界：被讓位的是「寫功課固定 100%」**這一條規則**，其餘課程規則照跑。帶特殊折扣又報寫功課的學生，其安親／課輔適用率依各自的一般規則處理 —— 安親仍套園內生 `max(0.9, basicRate - 0.05)`，課輔不套園內生額外優惠。美語／數學（R15）本就不經寫功課判斷，維持 basicRate。

### R13：安親點名表

來源 TA!B6（其餘學生區同型）。若該學生整段班級文字含寫功課或歷史美安，**且無特殊折扣（R07 未命中）**，適用率為 1。否則若園內生，`max(0.9, basicRate - 0.05)`；其他 basicRate。

這裡的 max 表示最低收到 90%：基本 95%→90%、100%→95%、基本 85%→90%。最後一例與「越折越優惠」直覺不同，必須留下測試／待確認，不偷偷改成 min。條件是整段報名文字，不能不經確認就改為僅目前選中班名。

### R14：課輔點名表

來源 TT!B6：含寫功課且**無特殊折扣**時適用率 1，否則基本率；沒有額外園內生 -0.05。

R13 的折扣文字依序為百分比＋兄弟姊妹「親」＋園內生 `CHAR(10)` 換行與「(園)」。R14 僅百分比＋「親」，沒有「(園)」。旗標不參與算術，模板必須保留順序和換行。

### R15：其他模板

美語兩種模板 D5、數學模板 B7 直接使用 D!H 基本率，附兄弟姊妹「親」標记。加強班／國語文模板 B 欄有 % 標頭，但本次 B6/B7 空白；不可擅自填入基本率當作已知收費規則。P1 對這類課程保留基本率供參考，課程適用率標示 `not_configured`。

### R16：狀態與說明契約

R17／R18 是學生層級提醒，併入 hasIssues，不將已算出的數值改成 unavailable，也不阻止建立 run；相依排課缺漏仍依原契約標 needs_review。

每個輸出都有 value、status、ruleIds、sourceRefs 與 issues。status 至少 `calculated`、`not_applicable`、`unavailable`、`needs_review`。null 不代表 0；false 不代表缺資料；顯示文字不參與後续算術。

人工更正入口是修正排課／別名或 ERP 標籤後重匯，不以修改備註覆蓋正式優惠；P1不直接覆寫結果。未來單筆override另立有原因、期限、課程與歷程模型。

### 9.1 班級類別與固定 5 天屬性（D37 1）

每個班級設定包含兩項核心屬性（自動偵測＋可手動覆寫）：
- **折扣類別（category）**：`care`（安親課輔班）、`math`（數學班）、`english`（美語班）、`none`（不列入折扣）。
  - 自動偵測規則（有序判定）：
    1. Q1：名稱含「寫功課」→ 不列入（`none`，寫功課優先）。
    2. Q2：名稱包含「國小輔導」、「安親」、「課輔」→ 安親課輔班（`care`）。
    3. 名稱包含「國小數學」→ 數學班（`math`）。
    4. 名稱包含「兒童美語」→ 美語班（`english`）。
    5. 其餘名稱 → 不列入（`none`）。

### 9.3 衝堂扣天選班演算法（D37 2②、S manifest §7.5）

針對 `math` 與 `english` 類別，若學生報名同類別多個班級，改取該類別中對學生適用側扣除量最多的班，取代 v2「只取第一班」：
1. **適用側判斷**：年級小一／小二看安親側；小三至小六看課輔側；其餘年級無適用側取首班。
2. **正量扣除量比較**：各班先依 D24 取整得 rounded（負值），扣除量正量為 `-rounded`，選正量最多者（即 rounded 最負者），嚴禁以 `Math.max(rounded)` 誤選少扣者。
3. **平手穩定規則**：正量扣除量相同時，取報名順序在前者（`token_index` 較小者）。
4. **候選可計算性與 fallback（Q5／Q6）**：
   - 僅找不到課表（`schedule_not_found`）或課表空白（`schedule_empty`）視為不可計算；若有可計算候選，僅在可計算候選中比較，不可計算者扣天視為 0 但保留其 `SCHEDULE_NOT_FOUND` 需確認警告。
   - 含未知星期候選（Q5-B）以 fail-closed 值參與比較，並保留 `UNKNOWN_WEEKDAY` 警告。
   - 全部候選皆不可計算時，沿用首班 0 fallback 並保留警告。
5. **美語缺課表警告（F-8）**：v3 補齊美語班找不到課表時出 `SCHEDULE_NOT_FOUND` 警告（v2 維持不警告）。

### 9.4 R11／R12 固定 5 天下限與適用率 100%（Q7-A、D51；**v4 已廢除適用率 100%，見 §9A**）

若學生報名之班級任一具備固定 5 天旗標（`fixedFiveDays === true`）：
- 安親／課輔收費天數：固定 5 天為衝堂扣天的地板，額外扣天在固定 5 天之後套用，但整體仍受年級下限保底（小一二安親最低 3.5 天、小三至六課輔最低 3.0 天，不被額外扣天穿透；D51）：
  `baseVal = max(5 + maDed + enDed, 5)`
  `days = max(年級下限, baseVal - extra)`
  例如：年級 4、固定 5 天且額外扣 2 天時，天數為 `max(3.0, 5 - 2) = 3`（原公式將固定 5 天置於 MAX 第三參數導致 extra 被壓回 5 天，屬歷史規則缺陷，於 #147 以 `extraDeductionAfterFloor` 旗標於 v3 修正；v1／v2 與 compat 軌維持凍結）。此天數計算不受特殊折扣影響。
- 安親／課輔適用率皆為 100%（10000 bps）；**例外**：學生帶特殊折扣標籤（R07 命中）時，依 §8 優先序不套用此 100%，改走 R13／R14 的一般規則處理特殊折扣率。
- 不列入但固定 5 天的班（如寫功課），本班適用折扣顯示 100% 而非「未設定」。

此處的「顯示 100%」與「適用率 100%」是**兩件事**，不可互相推論：

| 對象 | 語意 | 100% 的來源 |
|---|---|---|
| 本班適用折扣顯示（`applicableRateForClass`） | 該**班級自身**不適用一般折扣規則（不列入比較、固定 5 天下限），因此不取學生層的折扣欄位，直接呈現 100% | 班級屬性 |
| 學生層安親／課輔適用率（`applicableAnqinBps`／`applicableTutoringBps`） | 該學生報名組合下的**課程適用率**；固定 5 天會使其為 100%，但特殊折扣優先 | 學生折扣規則 |

換言之，「本班顯示 100%」不表示學生的基本折扣被蓋掉；反之亦然。帶特殊折扣的學生其基本折扣與適用率一律照標籤算（§8 優先序），畫面與對帳工具都應讀到該值。

### 9.5 R17 isEnrolled 與重複報名提示（Q3、Q8）

- **isEnrolled（Q3）**：是否報名安親／課輔依安親課輔班類別（`category === 'care'`）＋年級判定。只有寫功課班者 `isEnrolled` 為 false（不列入比較，無 UI 影響）。
- **重複報名提示（Q8）**：
  - 同折扣類別（`care`、`math`、`english`）報名 ≥ 2 班時出 `DUPLICATE_SUBJECT_ENROLLMENT`。
  - 加上 Q8：「固定 5 天且不列入」（`fixedFiveDays === true && category === 'none'`）之班級報名 ≥ 2 班時亦出提示（保留寫功課重複提示，不擴及交通車等一般 none 班級）。

### 9.6 未對應班處理（D37 3、Q4）

- 名冊班名有對應系統班級：用該系統班級設定（類別、固定 5 天、時段）。
- 名冊班名未對應系統班級：依米豆奶班名套用同一自動偵測照常計算，且若類別為 `care`、`math` 或 `english`，標記需確認警告 `CLASS_NOT_MAPPED`（「班名未對應課表，請確認米豆奶班名或系統班級名稱」；`none` 類別不出）。
- 未對應的數學／美語班無時段時，扣天沿用 0 fallback＋缺課表需確認。

### 9.7 歷史診斷標籤分解（Q12、S manifest §5；#159 PR-1 起不再供新 run 使用）

以下記錄 #112/#161 時期的實作與 issue-code 語意；PR-1 停止新 run 的兩個計算呼叫及 warning productions，並停止新寫 diagnostics snapshot。此節是歷史契約，不代表新 run 仍執行雙軌診斷。

v3 計算同時對照 shadow(v2) 與 compat：
- `formal(v3)` vs `shadow(v2)` 天數不同 → 標記 `RULESET_POLICY_DIFFERENCE`（白話「新舊規則對這位學生的算法不同」）。
- `shadow(v2)` vs `compat` 天數不同 → 標記 `NUMERIC_POLICY_DIFFERENCE`。
- 兩者分開標示，可並存。舊 run 標籤不變。

## 9A. erp-tag-v4 規則段（#112；課程學費折扣與固定 5 天解耦）

正式軌 `erp-tag-v4` 於 #112 落地（授權：06 D52、`specs/14` §3.4、§6 第 4 點）。它**只**改動「課程學費折扣」與「本班適用折扣」的判定來源；天數公式（含 #147 的額外扣天順序）與 §9 其餘規則完全不動。

### 9A.1 版本註冊與能力旗標

- `FormalRuleSetVersion` 新增 `'erp-tag-v4'`；`TARGET_FORMAL_RULE_SET_VERSION` 改為 `'erp-tag-v4'`（空 DB 的預設目標正式軌）。
- `RuleSetCapabilities` 新增 `homeworkDiscountDecoupled`：`v4` 為 `true`；`v1`／`v2`／`v3`／`excel-v260922-compat`／未知字串為 `false`。行為差異一律讀旗標，禁止字面版本比較（03 §5.3.1）。
- 既有 v2／v3 DB 不因目標版本改為 v4 而被靜默升級；仍須使用者明確確認（Q11）。

### 9A.2 學生層課程學費折扣：不再讀固定 5 天（A15）

`erp-tag-v4` 下 `calculateApplicableRate` 不套用 `hasHomeworkOrMeian` 造成的 10000 bps 覆蓋（`homeworkDiscountDecoupled = true` 時 `homeworkOverwriteApplies` 恆為 false）。因此：

- 安親／課輔收費率完全由**有效科數**（§9.2 類別式）、園內生優惠（R13，僅安親側 `max(9000, basic − 500)`）、兄弟姊妹（R06）與特殊折扣（R07，仍為最高優先）決定。
- 同一學生勾選與不勾選固定 5 天，六個課程的學生層收費率完全相同。
- **固定 5 天的天數地板照舊保留**：`calculateCareDays` 仍收 `hasHomeworkOrMeian` 作 `homeworkFloor`，天數公式與 §9.4 的地板語意不變（見 §9A.4）。

手算對照（前提：無特殊折扣、無兄弟姊妹）：

| 報名組成（含任一 `fixedFiveDays === true`） | v3 安親／課輔 | v4 安親／課輔 |
|---|---|---|
| 輔導班（`care`，固定 5 天）＋數學班（`math`）＝ 2 科 | 10000 | **9500** |
| 同上且帶「園內生」，小一／小二 | 10000 | 安親 **9000**（9500 − 500）；課輔仍 9500 |
| 只報寫功課班（`none`，0 科） | 10000 | **10000**（科數 0 → 基本率） |
| 寫功課（`none`）＋輔導（`care`）＝ 1 科 | 10000 | **10000**（科數 1 → 基本率） |
| 美語／數學課程收費率 | 即 `baseDiscountBps` | 不受影響 |
| 帶特殊折扣標籤（R07） | 特殊折扣優先 | 不變 |

**收費方向**：bps 是收費率，10000＝全額、9500＝付 95%。此變更降低同時具備固定 5 天與多科折扣資格學生的安親／課輔收費率，**對學生有利**。

### 9A.3 逐班層「本班適用折扣」：完全由 `category` 決定（A16）

`applicableRateForClass` 在 `erp-tag-v4`（具快照的 run）下不再因 `fixed_five_days === 1` 強制回傳 10000 bps，改為完全依快照的 `category`：

- `care` → 小一／小二取 `applicableAnqinBps`；小三至小六取 `applicableTutoringBps`；其他年級為 `null`。
- `math` → `applicableMathBps`；`english` → `applicableEnglishBps`。
- `none`（即使該班勾選固定 5 天，如寫功課）→ `{ status: 'not_configured' }`：畫面顯示「未設定」，帳務比對工具標為「無法判定」。
- 缺該班快照 → `not_configured`（不得以當前班名猜測，03 §5.3.4）。

**學生層 vs 逐班層不可混稱**：`none` 班級的**學生層**收費率照常依總科數計算（只報該班時科數 0 → 10000，**不是 null**）；逐班層的「未設定」是 `applicableRateForClass` 對單一 `none` 班級的回傳值。

### 9A.4 不變的部分（避免誤解為連帶移除）

- **天數公式不動**（`care-days.ts`）：固定 5 天仍是衝堂扣天地板，額外扣天在固定 5 天之後扣除並受年級下限保底（D51、#147）。
- **`isEnrolled` 保留**：仍依 `category === 'care'` 與年級判定，管天數適用性與顯示，不參與課程學費折扣判定。
- **重複報名提示不變**（§9.5）：`fixedFiveDays === true && category === 'none'` 仍列入提示條件。
- **§9 其餘規則不變**：類別式科數（§9.2）、選班演算法（§9.3）、未對應班（§9.6）、診斷標籤分解（§9.7）。

### 9A.5 匯入異動與影響預覽的歸因（A15 後半）

`roster-changes` 在 `erp-tag-v4` 下停用「寫功課／美安（或任一固定 5 天班）→ 安親／課輔回到 10000」的折扣變動歸因：加入或退出這類班級不再被列為折扣變動原因（它已不改變折扣，只可能改變天數，仍以天數變動呈現）。歷史版本（`v1`／`v2`／`v3`／`compat`）軌道之歸因保留，維持版本隔離（A17）。

### 9A.6 類別「未設定」（`unset`）語意（#157；06 D53）

`erp-tag-v4` 起（#157 落地），「列入多科折扣」的類別**不再由班名推導**，一律是使用者（或既有設定）的明確決定。

**五個類別值與其語意**：

| 值 | 語意 | 計入多科折扣科數（§9.2） | 學生層課程學費折扣 | 逐班本班適用折扣（§9A.3） |
|---|---|---|---|---|
| `care` | 安親課輔班 | 是 | 依有效科數 | 依年級取安親／課輔 |
| `math` | 數學班 | 是 | 依有效科數 | 數學適用率 |
| `english` | 美語班 | 是 | 依有效科數 | 美語適用率 |
| `none` | 使用者**明確**指定「不列入折扣」 | 否 | 依有效科數 | `not_configured` |
| `unset` | 使用者**尚未指定** | 否 | 依有效科數 | `not_configured` |

- **`none` 與 `unset` 在計算上完全相同**（皆不計科數、逐班層皆 `not_configured`）；差異**只在呈現與提示**：`unset` 在畫面顯示「（未設定）」並引導使用者補設定。不得把 `unset` 呈現成 `none`——那等於**替使用者陳述一個他沒做過的決定**。
- **科數計算排除 `unset`**（§9.2 的類別集合只收 `care`／`math`／`english`）。
- **來源狀態**：`categorySource` 值域為
  - `'manual'`：使用者明確指定。
  - `'seed'`：**seed 基準**（機構既有的班級設定；**不是**使用者的決定）。
  - `'unset'`：未指定——可能是使用者明確撤回（選回「（未設定）」），也可能從未被指定。
  `'auto'`（舊的班名推導）僅作為舊資料的讀取值存在，其值一律不採用（不得把系統的猜測升格為使用者的確認）。

**seed 基準（機構既有設定）**：

- seed 49 個既有班級的類別基準由 `SEED_CLASS_CATEGORIES` **逐班明列**（`care` 8／`math` 12／`english` 24／`none` 5，依**課程性質**判定，非班名關鍵字比對；與 #157 之前的 `detectClassCategory` 對這 49 個班名的判定結果逐班相同）。
- 基準在**讀取設定時**套用，**不寫進草稿**。如此全新 DB（seed 草稿）與既有 DB（已儲存設定）走**同一條**基準路徑，對同一份設定算出**相同**結果。
- **適用優先序**：`manual`（使用者的決定）> `unset`（使用者明確撤回）> `seed`（基準）> 未設定。
  使用者撤回後重新讀取仍是 `unset`——**不得**被基準還原（撤回必須真的撤回）。
- 使用者在課表設定**新增**的班（不在 seed 49 班內）**不適用基準**，一律為未設定：基準是既有機構設定，不是可推廣的規則。

**未對應班的處理（Ruling 3）**：名冊報名的班名**未收錄於課表設定**時（`mapped = false`）：

- 類別一律為 `unset`、來源為 `unset`、`fixedFiveDays` 為 `false`——**不論班名為何**（含舊制會被自動偵測為 `care`／`math`／`english`／`none` 的寫法）。
- **一律產生 `CLASS_NOT_MAPPED` 需確認警告**（舊制只對 care／math／english 警告；被偵測為 `none` 的班名靜默無警告，使用者無法從結果反推「這班根本沒被收錄」）。
- 該班對學生之**折扣與天數影響為零**：不計科數、不觸發天數地板、不作為選班候選。

**版本邊界與重算差異（Ruling 7）**：本節描述的是**現行規則**（`erp-tag-v4`），且同一類別語意亦用於 `erp-tag-v3` 重算；不為 v3 保留舊的班名類別推導，也不新增 rule-set 版本。以同一份本機 `data/app.sqlite` rev 82 設定與 431 名學生，比對 `main@83b0127` 和 PR #160 前一版 `c595f4f` 的完整計算輸出（科數、基本折扣、安親／課輔天數與 issue code 集合逐位元比對）：`erp-tag-v1` **0/431**、`erp-tag-v2` **0/431**、`erp-tag-v3` **154/431**、`erp-tag-v4` **154/431**、`excel-v260922-compat` **0/431**。v3／v4 的 154 筆差異是 40 筆科數／基本折扣改變與 139 筆 issue code 集合改變（新增 `CLASS_NOT_MAPPED`）之聯集。這是本機真實資料的單次量測，不是 CI golden 或對所有資料集的保證；相應不變式測試見 `d1-invariance` 與 `issue-112-v3-invariance`。已持久化的歷史 run 不重算、不改寫（03 §4）；其既有快照依儲存的 `category` 讀取，不在讀取時把 `source='auto'` 轉成 `unset`（03 §5.3.4）。§9 的 v3 原文保留供歷史版本對照。

## 10. 已觀察但尚未由業務批准變更的差異
1. 每週星期沒有參與重疊判斷（已於 D30 拍板批准改為同星期比對，實作於新版 `erp-tag-v2`；舊版 `erp-tag-v1` 維持原樣不變；v3 沿用同星期比對）；同時段兩班不做 union 則持續保留。
2. 科數算類別存在性，且整段寫功課扣 1；同類多班只取第一個來扣天（v1/v2 行為；v3 已由 §9 取代）。
3. 缺課表 VLOOKUP 失敗當 0，原表可能顯示完整 5 天。
4. 安親園內生＋特殊低折扣可能被調整回 90%。
5. 無安親／課輔 enrollment 的學生也按年級產生天數。
6. C表B:E只填4–57，共54個彙整槽；目前spill為49班加1空白，共50槽，僅餘4槽。超過有公式的槽可能得到空白／0扣天（不必然是#N/A）。另D填至1000、SUMIF至S!96、TEXTJOIN至S!115。新工具不照抄固定容量、查找範圍漂移與跨年限制，須有對照證據。

原則：可延續相容結果並加具體提示，讓 prototype 可操作；涉及收費意義改變的選擇記入新 ruleSetVersion 並確認，不覆蓋舊 run。
