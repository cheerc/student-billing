1. **權威欄位是「標籤」**。成因是 ERP 改版造成匯出欄位漂移。使用者目前的 workaround 是**把標籤欄複製貼上覆蓋備註欄**。

## 1. 結論

**需先修正指定問題，才可進入 P1 implementation plan。**

規格的「規則轉譯」品質很高：R01–R16 的公式語意、MAX 括號位置、負數取整分支、園內生 `MAX(0.9, …)` 的反直覺結果、VLOOKUP 範圍漂移、模板容量與列印設定，我逐項回到 XLSX 核對後**均正確**；U01–U40 的 expected 值我逐項驗算後**未發現算錯**；我以獨立實作重算 477 列 × 8 欄 = **3,816 格全部與 Excel 快取相符**。

阻擋 P1 的是規格把**規則的輸入來源綁錯了一個欄位**，且在同一份證據前推出了相反的結論：

> **F01（P0，使用者已確認）**：所有備註型規則的公式讀 `Sheet1!$I`（**備註**），但 ERP 改版後已把結構化標記移到 `Sheet1!$H`（**標籤**）。樣本中 **226 / 477 人的標籤欄有值**——133 筆兄弟姊妹、97 筆園內生、14 筆特殊折扣、14 筆額外扣天——在未套用 workaround 的檔案上**全部沒有生效**。規格 `02:32`／`02:111` 把這個缺陷寫成了「不得違反」的硬性規則。

**阻擋 P1 的項目：F01、F02、F03、F04、F08。**
F01 決定 P1 要重現哪一種行為；F02 決定 golden 測試會把哪一種行為鎖成「正確答案」；F03 是 ERP 已有、規格未辨識的核對維度，使用者已確認其語意；F04 是樣本內已發生、且**不可自動修正**的排課缺漏；F08 是班名解析策略，使用者已明確授權突破 Excel 的限制，必須在 plan 前定案。

**不阻擋 P1**：F05（降級）、F06、F07、F09–F15。**P3 點名表未做原生列印驗收，不是 P1 阻擋項目**；規格對此的處理（`05` §1、§7）正確且誠實。

## 2. Findings（依嚴重度排序）

### F01 — P0 — 備註型規則讀錯欄位（使用者已確認為 ERP 改版造成的欄位漂移）

**狀態**：r1 提出，使用者已確認。「標籤」為權威欄位。

**Spec 位置**
- `02-calculation-rules.md:32` — 匯入契約表：`|標籤|H1|選用|保留但目前公式未用；**不得取代備註**|`
- `02-calculation-rules.md:111` — 「以下都搜尋 RAW **備註 I 欄，不是 H 標籤欄**。」
- `02-calculation-rules.md:113–118` — R05–R08 規則表，來源標為 `D!G2/J2/K2/L2`
- `02-calculation-rules.md:122` — 「本次樣本 477 人沒有額外扣天、兄弟姊妹或特殊折扣的有效快取，只有 1 名園內生。」

**原始證據**

公式原文（`xl/worksheets/sheet9.xml`，D 表第 2 列）四條全部指向 `$I`：

```
G2 = IF(NOT(ISERR(SEARCH("安課額外扣0.5天",Sheet1!$I2))),0.5, … )
J2 = IF(NOT(ISERR(SEARCH("有兄弟姊妹折扣", Sheet1!$I2))), "Yes", "")
K2 = IF(NOT(ISERR(SEARCH("特殊折扣95折", Sheet1!$I2))), 0.95, … )
L2 = IF(NOT(ISERR(SEARCH("園內生", Sheet1!$I2))), "Yes", "")
```

兩欄的實際內容（計算檔 Sheet1 與 ERP 原始檔的 A:J 逐格比對 **0 筆差異**，故非兩檔版面不同）：

| 關鍵字 | 出現在 **H 標籤** | 出現在 **I 備註** |
|---|---:|---:|
| 有兄弟姊妹折扣 | **133** | 0 |
| 園內生 | **97** | 1 |
| 特殊折扣 9/8/7/85 折 | **14** | 0 |
| 安課額外扣 0.5/1/2 天 | **14** | 0 |

標籤欄完整值域：`有兄弟姊妹折扣`、`園內生`、`特殊折扣9折/8折/7折/85折`、`安課額外扣0.5天/1天/2天`、`員工家屬`、`有搭車`、`需月繳`。前三類與公式搜尋字串**逐字相同**。

**影響（以標籤為來源重算 477 人的差異）**：基本折扣改變 **107 人**（1→0.95 共 53、0.95→0.9 共 40、1→0.8 共 7、1→0.7 共 2、其餘 5）、課輔天數改變 **12 人**、園內生旗標改變 **98 人**（其中 54 人為小一／小二，直接改變安親點名表的課程適用折扣）、額外扣天 14 人、特殊折扣 14 人。

**r2 新增：workaround 的兩個副作用**

使用者目前以「複製標籤欄貼上覆蓋備註欄」繞過此缺陷。這帶出兩點規格必須處理的事：

1. **備註的自由文字每次都被銷毀**。備註欄 171 筆非空值全是營運資訊，其中數筆直接描述會影響扣天的出席例外，例如第 325 列的 `週三不進班，平日17:30就離開`、另有 2 筆 `一、四不進班，在外面上數學。`。workaround 執行後這些文字即被覆蓋。**新工具同時原生讀取兩欄，可直接消除這項資料損失**，這是遷移的具體效益，應寫進 `01` 的產品目的。
2. **本次提供的檔案是「未套用 workaround」的狀態**（備註仍為自由文字）。因此 `evidence/cached-summary-baseline.json` 與 Excel 內的既存快取**記錄的是缺陷狀態，不是使用者實際作業時的狀態**。這使 F02 從「可能」變成「確定」。

**最小修正建議**
1. 刪除 `02:111` 的「不是 H 標籤欄」與 `02:32` 的「不得取代備註」。
2. 匯入契約改為：`標籤 H1` = **P1 必需標頭，規則主來源**；`備註 I1` = P1 必需標頭，自由文字，**次要來源**（相容用）。
3. 規則輸入來源參數化為 `noteSourceColumns`，預設 `["標籤","備註"]`，命中時記錄**來源欄位**於 provenance，兩欄皆命中且值不同時標 `CONFLICTING_NOTE_SOURCE`。
4. 保留兩個 ruleSetVersion：`excel-v260922-compat`（讀 `備註`，僅供與既有快取比對）與 **`erp-tag-v1`（讀 `標籤`，P1 預設且為正式值）**。
5. `02:122` 整段改寫：樣本**有**充分的特例案例，只是被讀錯欄位遮蔽。
6. `員工家屬`（14）、`有搭車`（46）、`需月繳`（1）三種標籤無對應規則，一律保留原文、**不解讀**、不產生任何折扣，並列於明細抽屜。

**受影響階段**：P1。

**驗收方式**：以樣本匯入後，`erp-tag-v1` 模式下兄弟姊妹命中 133 筆、園內生 97 筆、特殊折扣 14 筆、額外扣天 14 筆；且可一鍵產出與 `excel-v260922-compat` 的 107 筆折扣差異報表。

### F02 — P1 — TDD 的 fixture 與 golden 策略會把缺陷鎖成正確答案

**狀態**：r1 提出；因 F01 已確認且 baseline 確定取自缺陷狀態，本項由「風險」升為「確定」。

**Spec 位置**：`04-tdd-acceptance.md:16`、`04:17`、`04:50–53`（U21–U25）、`04:96–100`（黃金比對）；源頭是 `02:122`。

**原始證據**：`cached-summary-baseline.json` 的 477 人八欄取自未套用 workaround 的檔案，其中兄弟姊妹／園內生／特殊折扣／額外扣天**全部未生效**。規格看到「快取全空」，推論為「樣本未涵蓋，需合成測試」，而未追問「為什麼 477 人的機構沒有任何兄弟姊妹折扣」。

**具體觸發例**：依 `04:96` 建立 golden 後，U21（1 科＋兄弟姊妹 → 9500）在合成 fixture 上綠燈，同時真實 133 人的 golden 把「兄弟姊妹不生效」鎖為期望值。兩者都通過，缺陷被固化，而 `04:98`「未查明不能更新 expected 消除紅燈」反而會阻止修正。

**最小修正建議**

2. 新增一組 **real-sample 特例測試**：以樣本中 133/97/14/14 筆標籤學生為輸入，斷言規則有命中（在 compat 模式下應為 red）。
3. `04:98` 的差異分類新增「**來源欄位缺陷（F01）**」一類，允許依使用者已確認的決策更新 expected。
4. 合成 fixture 保留，覆蓋樣本中為 0 的分支（`安課額外扣1.5天`、`特殊折扣95折`）。
5. 建議另取一份**已套用 workaround 的 Excel 副本**重算，作為 `erp-tag-v1` 的獨立對照基準；這是目前唯一能在不寫產品程式的情況下取得原生 Excel 驗證的途徑。

### F03 — P1 — ERP 班名 token 已內含每週收費級距（使用者已確認語意）

**狀態**：r1 提出，使用者已確認：`[3_5]` = 3.5、**無後綴 = 5 天**、只有安親／課輔有分天數。

**Spec 位置**：`01-product-spec.md:31`（每週收費天數定義為純計算值）、`02:44–46`、`03-architecture-api.md:56`。

**原始證據**：`2026-09-01_2026-09-30_財務報表(Sample).xlsx` 的「班級營收狀況」I1:W1 欄標題即完整 ERP 班名，其中 `115國小輔導-三年級[團][3]`、`[4]`、`[3_5]`、`[4_5]` 並列為同一班的四個獨立收費欄。ERP 學生檔的班名 token 同樣帶這些後綴。

樣本中一般國小輔導 token 共 **179 筆**：帶後綴 141 筆（`4_5`×45、`3`×36、`4`×32、`3_5`×28）、無後綴 38 筆（= 5 天）。兒童美語與國小數學 token 的 `[W1]`／`[Starter]` 等後綴**不是**級距，與使用者說明一致。

**r2 新增：完整核對結果**

以 `erp-tag-v1`（標籤為規則來源）、無別名、無後綴視為 5 天，對全部 179 筆做核對：

| 設定 | 一致 | 不一致 | 一致率 |
|---|---:|---:|---:|
| `excel-v260922-compat`（讀備註），僅帶後綴 141 筆 | 128 | 13 | 90.8% |
| `erp-tag-v1`（讀標籤），僅帶後綴 141 筆 | 139 | 2 | 98.6% |
| **`erp-tag-v1`，全部 179 筆（無後綴 = 5）** | **174** | **5** | **97.2%** |

無後綴的 38 筆中 35 筆吻合 5 天，佐證使用者的說明。**剩餘 5 筆即為真正需要人工判讀的核對項目**：

```
列 30   小一  115國小輔導-一A[團]        ERP 5     算出 4.5
列 35   小一  115國小輔導-一A[團][4_5]   ERP 4.5   算出 4
列 43   小三  115國小輔導-三年級[團]      ERP 5     算出 4
列 51   小一  115國小輔導-一B[團][4_5]   ERP 4.5   算出 4
列 52   小四  115國小輔導-四年級B[團]     ERP 5     算出 4
```

**影響**：使用者需求第 4 條是「協助正確開繳費單」。ERP 檔裡本來就有可比對的第二來源，規格卻只輸出單一計算值。納入後，477 人的核對工作可收斂成 5 筆人工判讀。

**最小修正建議**
1. `EnrollmentSnapshot` 增 `erpBillingTierRaw`（原始後綴字串，無後綴為 null）與 `erpBillingTier`（解析值；無後綴 → **5.0**；只對安親／課輔科別解析）。**不參與計算**，僅作比對。
2. `StudentCalculation` 增 `tierComparison: {computed, erpDeclared, status: match | mismatch | not_applicable}`。
3. 總表增欄「ERP 登記級距」與篩選 `tierComparison=mismatch`；`01:54` 的篩選清單相應補上。
4. `GET /students` 增 `tierMismatch` 白名單參數。
5. mismatch **不得**自動修正任一方，一律標 needs_review 交人工。

**受影響階段**：P1（資料模型、UI、API）。

**驗收方式**：匯入樣本後，以 `erp-tag-v1` 計算並篩選 tier mismatch，**結果應恰為上列 5 筆**。這是一個可數、可回歸的驗收數字。

### F04 — P1 —（**r2 方向修正**）缺排課的 13 名小一學生不可自動套別名，必須標示後交人工

**狀態**：r1 判定為「13 人被少扣天，屬靜默錯算」。**r2 依使用者 Q3 答覆實測後，此判斷方向需修正。**

**Spec 位置**：`02:192`、`02:162`、`04:65`（U33）、`01:110`。

**原始證據**：D!E2 以 `MID(C2, SEARCH("國小數學-", C2), FIND("[團]", C2, …))` 抽取第一個數學班，再 `IFERROR(VLOOKUP(…, C!$A:$E, 3, FALSE), 0)`。樣本中 13 名小一學生的抽取結果為 `國小數學-一[團]`，而排課表只有 `國小數學-一A[團]`（有時段）與 `國小數學-一B[團]`（**無任何時段**）。VLOOKUP 回 `#N/A`，被 IFERROR 吞成 0。美語側 313 筆抽取則 100% 命中。

**r2 新增的關鍵實測**：依使用者「沒有 A／B 就是該年級只有一個班」的規則，最自然的推論是把 `國小數學-一[團]` 對應到唯一有排課的 `國小數學-一A[團]`（扣天 安親 −0.5）。我實際套用後：

| 設定 | 級距核對一致 | 不一致 | 一致率 |
|---|---:|---:|---:|
| 不套別名 | 174 | 5 | **97.2%** |
| 套用 `國小數學-一[團] → 一A[團]` | 161 | 18 | **89.9%** |

**套用別名會讓 13 名學生的安親天數各減 0.5 天，並使這 13 人全部由「與 ERP 登記級距吻合」變成「不吻合」**（例：列 258 由 4→3.5，而 ERP 登記 `[4]`；列 264 由 4.5→4，而 ERP 登記 `[4_5]`）。

**影響與解讀**：ERP 登記的級距目前**支持現行的 0 扣天結果**。有兩種可能：(a) `國小數學-一[團]` 確實是與 `一A` 不同、且與安親時段不衝堂的班；(b) 人員是依 Excel 輸出回填 ERP 級距，因而循環吻合。兩者無法只憑檔案分辨。

**因此 r1 的「應該補扣天」是不安全的建議，r2 撤回。** 正確做法是：保持相容值、明確標示、交人工判讀——這恰好是規格 `02:162` 原本的精神，只是規格沒把它納入可驗收的數字。

**最小修正建議**
1. **不建立自動別名**。`國小數學-一[團]` 在別名未經人工指定前，一律 `schedule_not_found` + needs_review。
2. `01:103–113` 的 P1 驗收新增：**「抽取鍵無法在排課表命中的學生必須被明確列出，樣本預期為 13 人」**。
3. `04:96–100` 的黃金比對新增規定：**相同值但 status 不同者不算通過**——compat 值相同而新引擎標為 needs_review 屬正確行為。這是本案唯一能讓測試「看見」此缺陷的機制。
4. 課程設定頁在人員指定別名時，必須**同時顯示套用後的天數變化與級距核對影響**（本例：13 人 −0.5 天、級距一致率 97.2%→89.9%），讓人員在有後果資訊的情況下決定。這是把 F03 的核對能力用在設定流程上。

**受影響階段**：P1。

### F05 — P3 —（**r2 降級**）規格宣稱「ERP 檔沒有入退班生效日期」與事實不符

### F06 — P2 — R03 規定的「整數分鐘／有理數」與 Excel 的浮點語意不等價，規格卻宣稱不改語意

**Spec 位置**：`02:56`、`02:71`、`02:87`（「合併成同一區間**不改語意**」）、`02:99`、`04:37–38`（U09/U10）。

**原始證據**：Excel 的時間是日分數，重疊分鐘由 `(…)*24*60` 產生，**本來就不是整數**。實測快取：

- S!G5（名目 120 分鐘）= `120.00000000000006`
- S!G10（名目 120 分鐘）= `119.99999999999989` ← **同樣名目 120 分鐘，落在 120 的另一側**

R02 的課輔分支條件是 `IF(AND(I4>=120, …), -1, I4/60/3)`。若某時段的浮點值落在 119.999…（如 S 第 10 列的 13:20–15:20 模式），Excel 走 `-I/180 = -2/3`，而規格規定的整數分鐘實作走 `-1`，該班扣天由 `-0.5` 變 `-1`，**學生天數差 0.5 天**。R03 的 `MOD(x,1) < 0.3 / < 0.8` 邊界同理：總重疊 36 分鐘時，精確有理數 `f = 0.8` 取 `1`（結果 0），IEEE754 下 MOD 為 `0.79999999999999998…` 取 `0.5`（結果 −0.5）。

**我實際驗證的結果**：以兩條路徑（Excel 浮點重建 vs 整數分鐘／`Fraction`）逐班計算現有 40 個有時段班級，**兩路徑結果完全相同，且與 C 表快取 100% 吻合**。所有落在 120 邊界的課輔列浮點值都是 `120.00000000000006`（在 120 之上），因此**目前沒有實際分歧**。

**影響**：規格目前的說法是「這樣寫可以避免分歧」，實際上是「這樣寫會**製造**與 Excel 的分歧，只是現行排課資料剛好沒踩到」。S 第 10 列已證明 119.999… 真實存在。規格把它寫成等價改寫，實作者不會為它寫測試。

**最小修正建議**
1. `02:71`／`02:99` 改寫為明確的**刻意差異宣告**：「新引擎以整數分鐘計算，與 Excel 的日分數浮點在 `>=120` 與 `MOD` 邊界上**可能不同**；此為已登記的差異 DIFF-01，不是相容行為。」
2. 引擎保留 `floatCompatMode`，golden 比對時以 Excel 浮點路徑重現，用於證明差異只出現在邊界。
3. U04–U08、U10 補上**成對案例**：同一名目分鐘數分別以整數分鐘與浮點路徑求值，斷言兩者在 S 第 10 列模式（13:20–15:20 平移至課輔時窗）下確實不同，並斷言產品選擇整數分鐘。
4. `02:87` 的「不改語意」僅適用於 `f<0.5`/`f<0.8` 兩支合併（此點我已驗證確實等價），請把該句的適用範圍限縮，不可擴及整段浮點改寫。

**受影響階段**：P1。

### F07 — P2 — 「缺排課」有三種狀態，規格只處理兩種，第二種產品無法偵測

```

國小輔導-三年級[團]、四年級[團]、五年級[團]、六年級[團]
國小數學-一B[團]
```

（前 8 個是安親／課輔班本身，其時段即 `C1:D2` 的時間窗，無時段列屬正常；**`國小數學-一B[團]` 才是真正的異常**，見 F15。）

| 狀態 | VLOOKUP | 回傳值 | 產品可偵測？ |
|---|---|---|---|
| (a) 班名不在 C 表 | `#N/A` | IFERROR → 0 | 可（F04 即此類） |
| (b) 班名在 C 表但無任何時段列 | 成功 | **真 0** | **否** |

2. 判定依據改為**產品自有的 ScheduleSession 資料**（該 classId 是否有任何 session），不沿用 VLOOKUP 成敗。

**受影響階段**：P1。

### F08 — P1 —（**r2 升級並擴充**）班名解析策略：舊規則是工作表名稱子字串比對，且已有實際碰撞

**狀態**：r1 列為 P2。使用者已說明設計背景並授權新系統突破限制，且我實測到現行資料中**已存在碰撞**，故升為 P1（需在 plan 前定案）。


即：**名單 = 所屬班級文字「包含工作表名稱」的所有學生**（`FIND` 為大小寫敏感的子字串比對）。

**r2 新增：現行資料中已存在的碰撞**

```

  115國小輔導-四年級A[團] / [團][3] / [團][3_5] / [團][4] / [團][4_5]
```

**最小修正建議**

   ```
      withdrawal = null              ← (YYYY-MM-DD離班)，見 F05
   ```

   classId 以 `baseName`（＋必要時年度）建立明確 alias，**不使用子字串比對，不使用工作表名稱**。
3. `01:103–113` 新增驗收：對樣本中每一個有排課的班，產出「新 classId/alias 名單」與「legacy 子字串名單」的差異報告；差異必須逐筆可解釋（本樣本預期至少含 `國小輔導-四年級` 的 A/B 拆分）。

本報告的 P0 不是因為規格草率，而是因為一個**在原始 Excel 裡已存在、且被既有快取完美掩蓋**的 ERP 欄位漂移缺陷——規格甚至看到了它的症狀（`02:122`），只是做了相反的解讀。

## r3-3 補充 fixture A：DIFF-01 的實際分歧就是 spec 自己的 U06

`04:71` 明確要求「先確認具體案例確有分歧再斷言」。我以 1 分鐘精度掃描全部單堂時段（起 10:00–21:00、時長 30–240 分），對兩條路徑求值後得到**完整且可證的結論**。

**spec 現有的四個課輔邊界案例中，恰有一個分歧——U06：**

|案例|名目分鐘|Excel 浮點重疊值|`>=120` 浮點|`>=120` 精確|Excel 取整|精確取整|
|---|---:|---|---|---|---|---|
|U04 `16:30–18:30`|120|`120.00000000000006`|False|False|−0.5|−0.5|
|U05 `16:30–18:31`|121|`121.00000000000006`|True|True|−1|−1|
|**U06 `17:00–19:00`**|**120**|**`119.99999999999989`**|**False**|**True**|**−0.5**|**−1**|
|U07 `17:31–19:30`|119|`119.00000000000006`|False|False|−0.5|−0.5|

U06 是 `17:00–19:00` 這種完全尋常的兩小時課輔時段，且**已經寫在 spec 的測試矩陣裡**（`04:34`）。原生 Excel 會判 `>=120` 不成立而走 `-I/180`，erp-tag-v1 的整數分鐘策略判成立而走 `-1`，**單堂差 0.5 天**。

**完整特徵（可據此收斂 fixture 範圍）**：在 180 分鐘時間窗下，兩路徑只可能在**名目重疊為 36、120、126 分鐘**時分歧，其餘一律相同。原因是 `36/180 = 0.2`（`f = 0.8` 邊界）、`126/180 = 0.7`（`f = 0.3` 邊界）、`120` 為課輔特例門檻。安親側只會在 36 與 126 分歧；課輔側為 36、120、126。是否真的分歧還取決於起迄時刻的二進位表示，需逐案實算。

現有 49 班排課**沒有任何一班踩到**（我先前已逐班驗證兩路徑結果相同），故這是未來風險而非已發生錯算。

**建議修訂**
1. `04:34` 的 U06 改標為**已驗證的 DIFF-01 實例**，expected 同時保存兩值（erp-tag-v1 = −1；compat 浮點診斷 = −0.5），並斷言產生 `NUMERIC_POLICY_DIFFERENCE`。這樣 `02:102` 的 DIFF-01 條文就有了實測支撐，不再只是宣告。
2. `04:71` 可刪去「不宣稱原生 Excel 時段已重現」中關於**課輔平移**的保留——該問題已有答案；但「未經原生 Excel 重算」的限制仍成立，因為上述浮點值是我以 IEEE754 重建而非 Excel 實跑。
3. 課程設定頁在使用者輸入時段時，若名目重疊落在 36／120／126，可即時提示「此時段位於數值策略邊界，兩種算法可能差 0.5 天」。這比事後在核對表發現差異便宜得多。
