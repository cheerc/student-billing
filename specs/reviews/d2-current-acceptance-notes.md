# D2 現況與人工驗收底稿

本檔供 Lead 準備第三次驗收正式清單，不是 operator 已驗收的證明，也不是涵蓋批次 E 的最終清單。依 [06 D40](../06-handoff-decisions.md)、[03 §5.3–§5.4](../03-architecture-api.md)、[04 UX48–UX70](../04-tdd-acceptance.md)、[11 §8](../11-ui-acceptance-fix-plan.md)。已知缺口及證據見 [D2c parity／稽核](d2c-parity-audit.md)。D2 parent 必須等 D2d 合併才結案。

## 1. v3 如何生效

- 班級可選安親課輔、數學、美語或不列入折扣；固定 5 天是獨立旗標。自動偵測先處理寫功課；其餘依 D40 的包含式規則。手動值與來源一起保存，手動改名仍帶走；「恢復自動」依目前班名重新偵測，儲存與 reload 後也維持自動。
- v3 科數按折扣類別種數，不再用「寫功課減一」；同類數學／美語重複報名按適用側扣除正量最多選班，平手採報名順序。D24 取整、D30 同星期、窗口、正式標籤來源不改。
- 寫功課及美安的自動固定旗標會讓天數下限與安親／課輔適用率回到 5 天／100%；不列入但固定 5 天的班，本班適用折扣仍顯示 100%。
- 新 v3 run 的有效類別寫入 run 快照；舊 run 不重新分類。v3 歷史快照缺失應顯示無法判定，不以目前設定猜測。
- 未對應的 care／math／english 班會出 CLASS_NOT_MAPPED；兩段診斷區分新舊選班政策與 D24／歷史 Excel 數值政策。
- **已知缺口**：八項摘要與匯入異動明細仍取首班，尚未共用 v3 選中 token（D40 Q10）；空課表候選可能沒有需確認問題。這些由 D2d 修正，不能將 D2c 完整測試通過解讀為整個 D2 已符合規格。

## 2. 空 DB 與既有 v2 的差異

|狀態|目前版本決策與可觀察結果|
|---|---|
|空 DB，沒有 active run|目標正式版本 v3；課表頁不顯示升級勾選。儲存為 settings_only，只建設定版本，不建 run；影響人數為 null，UI 說明尚未匯入學生|
|已存課表，之後首次匯入／啟用|server 使用最新已儲存設定，新 run 採目標 v3；不需重新手動套一次課表|
|既有正式 v2 active run|讀取／部署不靜默升級；未明確選 v3 時 preview／apply／activate 維持 v2|
|歷史 v1／v2／v3 run|查詢固定於該 run 的設定／類別快照，不能用最新課表補算舊結果|

只用隔離服務與合成 fixture 的自動測試驗證上述路徑；本批不讀或操作日常真實 DB。

## 3. 升級操作步驟與目前限制

目標流程：開啟既有 v2 的課表頁→閱讀「改用新規則（v3）」說明→勾選→確認變更→檢視完整 v2-before／v3-after 差異→儲存並更新結果→確認新 run 為 v3、舊 v2 run 不變。

**D2c 現況限制（D2d 修正前不可驗收為完成）**：

1. application 升級預覽 before／after 目前都用 target，會漏掉同草稿單純切規則造成的差異；不能把「0 位受影響」當成已驗證沒有影響。
2. source 顯示僅勾選升級不納入 dirty，確認變更按鈕仍取決於設定是否有修改；升級-only UI 旅程未取得 runtime RED／GREEN。若同時有課表變更才可能開預覽，也不能藉此認定單純升級功能完整。
3. 既有 integration 已驗 preview 記錄 target、apply 新 run 版本與舊 v2 計算列不變；完整 v2 UI 旅程仍待補，空 DB 無 banner 的 E2E 不代替它。

Lead 最終清單應在 D2d 修正並驗證後，重新確認上述限制已消除再要求 operator 執行；不在此代 operator 驗收。

## 4. 班名比對報告與 Q13 提示

- 課表「班名對應」與匯入預覽共享班名比對 read model。米豆奶有／系統無列班數、去重學生數與報名筆數；系統有／本次名冊無帶上一份可證現行名單的人數與來源，沒有可證前份時明說不能判定，不拿 ready 批次冒充。
- 別名匹配有方向：米豆奶側 alias 到系統班算匹配；系統側僅 alias 覆蓋、沒有直接報名者仍列出並註記。一次多人／多班集合的人數不可直接相加。
- Q13：別名兩側自動偵測類別不同時，確認視窗顯示「類別將改由系統班決定」，可展開 raw→target 與類別；這是提示，不阻擋儲存。計算採系統目標班設定，alias 本身不承載類別。
- 現有 E2E 已驗跨類別提示可展開且可儲存，以及非跨類別不產生提示；寫入的 alias 會清理，避免下一案例／下一輪污染。

## 5. 影響預覽的新語意

- 修改類別，即使不改時段，也會影響科數與折扣；「受影響學生數」是天數、科數、基本折扣三類變動的 personCode 聯集去重，同一人只算一次。
- settings_only 不顯示虛假的「0 人變動」，而是尚未匯入學生的說明。
- 一般同版本設定變更已有科數／折扣及三項重疊去重測試；v2→v3 升級的 before 版本仍有前述缺口，兩種場景不可混稱為都完成。
- 保存應等待本次 apply response、dialog 關閉與 clean 狀態；成功 toast 是提示，不是識別多次儲存完成的唯一證據。

## 驗收安排

D2c 保留既有規則、不為 fixture parity 湊數；完整 fixture 與合成情境分開。D2d 收斂升級 preview／UI、共用 selection、既有班合併、空課表需確認與不足覆蓋；批次 E 的一般 UI 任務由 Lead 另行安排。正式第三次驗收檔由 Lead 產出，涵蓋 D2d 與批次 E 合併後的現況。本檔與 automated tests 不代替該人工驗收。
