# 13 課程類型分類與課表設定重構 Plan（#112）

日期：2026-10-18。依據：operator 2026-10-18 對話裁示（§0）。狀態：**spec 第四稿，實作未開始**。

前三稿曾提 dual review（PR #149），四位 reviewer 全部裁 REJECTED。本稿依 operator 隨後的裁示改寫 §0.2／§3.2／§3.3／§3.4——**其中 §3.4（課程學費折扣與固定 5 天解耦）是收費規則變更，不再是純 UI 重構**。

本檔是**行為契約**（要做成什麼、遵守什麼），不是執行計畫。實作計畫待 spec 通過 dual review 後另寫。

## 0. 商業需求（operator 2026-10-18 對話依據）

以下四點是本 spec 的根基，**任何實作或 review 與此衝突即為錯誤**：

1. **安親課輔班的基礎天數是 5 天，但衝堂要扣天。**五天是**基數**不是上限。數學班或美語班的時段與安親課輔班重疊就是衝堂，需要扣除衝堂天數以避免重複收費。**有些班級特殊、不列入衝堂扣費，所以需要一個旗標讓它們維持 5 天。這個旗標是使用者端的設定，不是系統判斷的。**
2. **兩個旗標都是「不因衝堂而扣天」，但分屬不同課程產品定位，兩者非等價、不得互相取代。**
   - **固定 5 天**＝該班級**預設不扣天數、不受衝堂影響**，係**課程產品定位差異**所致（安親課輔班的這個定位）。
   - **不計扣天**＝**特定時段**的班級雖然衝堂，但實際計費方式不扣天數，係**產品定位差異**所致（非安親課輔班這個定位）。
   - 兩者同時發生時，結果都是 5 天——那是巧合式的等價，**不是機制等價**（見 §3.2 的實測）。
3. **課程規劃分類**：「寫功課」「美安」是固定五天、不會被扣除天數的班級（商業需求）。數學班、美語班、作文班、國文班等都是**按堂計費**，一週可能一堂或兩堂，**不可能是一週固定五天**。
4. **輔導與寫功課／美安不會同時報名**。同一學生在「安親課輔班」類別只會報名一個班。

### 0.1 系統方向：不寫死，使用者自主決定

**收費方式由使用者決定，系統不預設。**operator 2026-10-18：

> 我自然會把寫功課／美安班去勾選不列入折扣啊，那是使用者自己決定的收費方式，現在系統不就是要往不寫死、使用者可以自主決定的方向走嗎？

具體含義：

- **課程學費折扣只由「列入多科折扣」的設定決定**，該欄位有四個選項：安親課輔班／數學班／美語班／**不列入多科折扣**。前三個把該課程歸入某一類折扣計算，第四個是不列入。
- **固定 5 天旗標完全不影響課程學費折扣**（§3.4）。
- 寫功課班、美安班要「不列入多科折扣」，由使用者自行勾選，**系統不依班名自動設定**。
- 建立班級時的每一個欄位，預設值都是中性值，**不代替使用者決定**。

### 0.2 學生視角與課程視角是兩份資料

operator 2026-10-18：

> `isEnrolled` 就不能拆，要保留，因為學生資料跟課程資料是兩個不同方向的資料，一個是學生角度，一個是課程角度。

`isEnrolled`（該生是否報名安親／課輔）屬**學生視角**，管的是天數計算的適用性與顯示，**不參與課程學費折扣判定**（§3.4）。

### 0.3 #112 的原始需求已過時

issue 標題要求「只對含關鍵字班級出現 checkbox」。operator 2026-10-18 明確指示「#112 就已經是個過時的需求了，要以現在討論的為主」。本 spec 依 §0 為準。

### 0.4 術語

| 本 spec 用詞 | 避免使用 | 理由 |
|---|---|---|
| 課程學費折扣 | 「適用率」 | operator：「那個叫做課程學費的折扣」。且 bps 數值越高代表學生付得越多，「適用率」易被讀反（現行文件即有此問題） |
| 安親課輔班（不輸入上課時間與星期） | 「不排課」 | operator：「什麼叫做不排課，這個用詞要改了吧」。安親課輔班本來就不以課表時段計算，直接說明該類別的輸入需求 |

**既有文件與程式碼中的「適用率」不在本 spec 內一併更名**（範圍過大）。但**新寫的 UI 文案一律用「課程學費折扣」**，既有顯示文字的更名列入 §6 待裁決。

## 1. 問題

現行課表設定的每一列都要求輸入星期與上課起迄時間（[09](./09-ui-workflow-redesign-spec.md) §3「五個編輯欄」），且每個班都出現「天數固定 5 天」checkbox（`web/src/components/settings/schedule-grid.tsx:431`）。但：

- 安親課輔班的星期與起迄**沒有計算意義**——系統已有固定窗口（安親 週一–週五 13:00–16:00、課輔 週一–週五 16:30–19:30，`web/src/domain/schedules/overlap-calculator.ts:7-12`）。輔導班的時段從不進入扣天公式（§2.1）。
- 「固定 5 天」這個旗標**只有少數課程產品需要**，但它出現在每一班，且現行的自動偵測（依班名含「寫功課」「美安」）是一組會隨班名改變而漂移的 hard code（§3.3）。
- 「固定 5 天」旗標還**不該管課程學費折扣**，卻透過 `homeworkOverwriteApplies` 強制安親／課輔課程學費收費率為 10000（§2.2、§3.4）。

## 2. 已證實的現況

所有數據皆由實際執行的探針取得。標「推論」者未經實測。

### 2.1 輔導班的時段完全不影響任何計算值

v3 的扣天候選以 `category==='math'|'english'` 篩選（`web/src/domain/billing/billing-calculator.ts:259,349`），`care`／`none` 進不去。實測（完整 classSettings 與 scheduleOverride，只改一個 `國小輔導-五年級` 班的 sessions，含整段落課輔窗口的時段 vs 無時段）：**IDENTICAL**——課輔天數 3.5、課程學費折扣 9500、`issues` 空。

*註*：9500 這個值來自「科數效應」（輔導＋數學＝2 科 → 基本收費率 9500）。

### 2.2 「固定 5 天」旗標的兩個作用

| 作用 | 位置 | 實測（輔導班勾選該旗標） |
|---|---|---|
| 安親／課輔收費天數的地板 `max(..., 5)` | `web/src/domain/billing/care-days.ts:32-33,49-50`（`homeworkFloor` 進 `Math.max`） | 課輔 3.5 → **5** |
| 安親／課輔課程學費收費率變 10000 bps | `web/src/domain/billing/discount-rules.ts:186`（`homeworkOverwriteApplies`）→ `billing-calculator.ts:495-509` | 9500 → **10000** |

**bps 語意提醒**：`applicableRates.*` 的數值是**收費率**，10000 = 全額（學生付 100%），9500 = 付 95%。數值越高代表學生付得越多。§3.4 的變更方向是**降低收費率**（對學生有利），不是提高。

副作用：受影響的班級那一列，其 `tierComparisons` 由 `match` 翻成 `mismatch`（ERP 登記級距 vs 計算天數）。其他班級的列不變。

適用率的 10000 只對「該生讀安親課輔」者成立——`hasHomeworkOrMeian` 與 `isEnrolledAnqin/isEnrolledTutoring` 在 `billing-calculator.ts:464-474` 是**兩條獨立算式**。

### 2.3 數學／美語班的時段確實進公式

實測（grade 4、輔導班＋數學班，數學週三 17:00–19:00 落在課輔窗口）：

```
數學有時段 → 課輔 4、收費率 9500
數學無時段 → 課輔 5、收費率 9500     → DIFFERENT
```

（4 天為精確值：重疊 150 分 ÷ 180 = 0.833… → D24 進位 1.0 → 5−1=4。）

**推論，待驗證**：若允許把數學／美語班設為免輸入時段的類別，該生天數會由 4 靜默跳成 5，收費金額隨之上升。

### 2.4 寫功課／美安班的時段不進公式

實測（寫功課／美安 有時段 vs 無時段）→ **IDENTICAL**（課輔 5、收費率 10000）。

### 2.5 分類自動偵測的邊界

實測 `detectClassCategory`（`web/src/domain/classification/class-category.ts:22-40`）：

```
美安 / 美安-三年級         category=none  detectFixedFiveDays=true
國小輔導-美安              category=care  detectFixedFiveDays=true
寫功課 / 寫功課-一A        category=none  detectFixedFiveDays=true
國小輔導-四年級 / 安親班 / 課輔-五年級  category=care  detectFixedFiveDays=false
作文-作文班 / 國文-小五 / 交通車 / 正音班  category=none  detectFixedFiveDays=false
兒童美語-Gino               category=english
國小數學-四A                category=math
```

`CARE_WORDS = ['國小輔導','安親','課輔']` **不含「美安」**，故 `detectClassCategory(班名)==='care'` 不能代表「安親課輔班」。**本 spec 不使用這個判斷**（見 §3.3）。

*審查歷程記錄*：PR #149 的審查過程中，曾有 reviewer 主張「seed 49 班中有 11 班 `detectFixedFiveDays` 為 true，成因『美安』是『數學』的跨字元子字串」。該主張經實測**不成立**——seed JSON 的 49 個班名中含「安」者為 **0 班**（`小六加強班-數學`.includes('安') 為 false）。該主張已於同輪審查中撤回。

### 2.6 「共用窗口」狀態不是機制，是偶然

| 新班名，佔位列 | `incomplete` | `SCHEDULE_INCOMPLETE` |

**推論，待驗證**：使用者新增一班安親課輔班時會看到「待補」與問題警示，而那是他選擇的課程類型、不是漏填。

## 3. 設計

### 3.1 課程類型（可擴充框架，只決定欄位存在）

新增班級層設定「課程類型」，由**使用者建立班級時選擇**，預設兩種：

| 類型 | 需要輸入上課時間與星期 | 專屬欄位 |
|---|---|---|
| **非安親課輔班** | 是（逐列輸入星期、起、迄、老師） | **不計扣天**（逐列） |
| **安親課輔班** | **否**（只填班級名稱、老師） | **固定 5 天**（班級層） |

- 兩種專屬欄位**互斥**：各類別只顯示自己適用的欄位。
- 框架設計為可擴充：新增類別時，該類別需要哪些欄位隨類別定義宣告。
- **不綁現有的 `category`（列入多科折扣）**。理由：兩者語意正交（§3.4），且 [02](./02-calculation-rules.md) §9.1 L281 寫的是固定 5 天旗標「**與類別獨立**」。（`detectClassCategory` 的名稱判斷**保留**，因 02 §9.1 L273-279 要求它。）

**風險（需實作注意）**：「課程類型」是第二個可獨立於 `category` 手動覆寫的持久化維度，與 #113／#122 剛修復的「兩欄各自手動覆寫、快照與名稱映射漂移」屬**同構的失敗模式**。實作時必須讓兩者的一致性在畫面上可見，不得任其靜默漂移。

### 3.2 兩個旗標非等價，不得互相取代

| 欄位 | 課程類型 | 層級 | 機制 | 課程產品定位 |
|---|---|---|---|---|
| **固定 5 天** | 安親課輔班 | 班級 | `Math.max(下限, 5 + 數學扣天 + 美語扣天 − 額外, homeworkFloor)`——**該生**的絕對地板，連其他班貢獻的扣天也一併抵銷 | 該班級**預設不扣天數、不受衝堂影響** |
| **不計扣天** | 非安親課輔班 | 每一堂 | 過濾該堂，使其不進扣天加總；**其他扣天管道照跑** | **特定時段**的班級雖然衝堂，但實際計費方式不扣天數 |

**實測證明兩者是不同的函數**（grade 4、輔導班＋數學班＋美語班，兩班時段各整段落課輔窗口 990–1170）：

```
無旗標，數學+美語都扣天        → 3 天
固定 5 天勾在輔導班（班級層）  → 5 天   ← 一次抵消兩個班的扣天
不計扣天勾在數學班那一堂      → 4 天   ← 只排除一班
不計扣天勾在數學+美語兩班     → 5 天   ← 必須逐堂勾，才等於固定 5 天
固定 5 天 + 數學不計扣天      → 5 天
```

**兩者同時發生時結果都是 5 天，那是巧合而非機制等價。**

**與 #147 的關係**：上表描述的 `homeworkFloor` 進入 `Math.max` 的行為，是 #147（OPEN）修正**前**的現狀。#147 的裁示是「安課額外扣天應在固定 5 天之後套用」。兩者必須一起理解：#147 調整的是額外扣天與這個地板的先後，本 spec 不裁定該順序（§6.3）。

### 3.3 預設值一律為中性，移除班名 auto 規則

- **所有班級的「固定 5 天」預設一律不勾**（`false`）。
- **移除**現行依班名含「寫功課」／「美安」的自動偵測（`web/src/domain/classification/class-category.ts:34-36` 的 `detectFixedFiveDays`）。
- **不新增任何替代的 auto 規則。**寫功課班與美安班要固定 5 天，由使用者在 UI 手動勾選。

**行為變更（需明確記錄）**：**auto 為 `true` 的寫功課班與美安班**，其預設值由 `true` 改為 `false`；**任何被手動設為 `true` 的班級**維持 `true` 不變（§3.9）。受影響班級的學生天數會改變——依 §0.1，旗標的存在意義就是切換天數，不勾當然會變。這是 operator 明確接受的預期行為。

**影響範圍**：已實測 seed 49 班中，`detectFixedFiveDays` 為 `true` 者為 **0 班**（無任何 seed 班名含「寫功課」或「美安」），故 **seed 集合內改變者為 0 班**。實際影響落在真實名冊中帶這些字樣的班級，以及使用者手動設過的班級（§7 列為未量測）。

**理由**：現行 auto 規則是「依班名判斷」，班名一改規則就漂移。依 §0.1「系統不寫死、建立班級由使用者決定」，此舉同時消除 hard code（全面清理見 #148）。

### 3.4 課程學費折扣只由「列入多科折扣」決定（**收費規則變更**）

**這是收費規則變更，非 UI 調整。**

- **移除** `discount-rules.ts:186` 的 `homeworkOverwriteApplies` 及其對 `anqin`／`tutoring` 的 10000 bps 覆蓋。
- **移除** `calculateApplicableRate` 的 `hasHomeworkOrMeian` 參數（`billing-calculator.ts:504-509` 的六個呼叫點隨之調整）。
- **固定 5 天旗標與「不計扣天」都不影響課程學費折扣。**
- 課程學費折扣的計算依據：學生的**科數**（由「列入多科折扣」分類決定，§2.1 的 9500 即 2 科的結果）、園內生優惠、特殊折扣標籤、兄弟姊妹折扣。**不讀固定 5 天旗標。**
- **「不列入多科折扣」的班，其學生的課程學費折扣不計算**（顯示「未設定」）。

**行為變更（實測）**：

| 學生 | 現行課程學費收費率 | 本 spec 後 |
|---|---|---|
| 報名寫功課班（安親／課輔） | **10000** | **9500**（2 科基本率） |
| 報名寫功課班且園內生（安親／課輔） | **10000** | **9000**（園內生優惠後的基本率） |
| 報名美安班（安親／課輔） | **10000** | **9500** |
| 美語／數學課程 | 不受影響（現行即 `baseDiscountBps`） | 不受影響 |
| 帶特殊折扣標籤 | 特殊折扣優先（`homeworkOverwriteApplies` 已含 `!hasSpecialDiscount`） | 不變 |

**收費方向**：數值是**收費率**，10000 = 全額、9500 = 付 95%。本變更**降低**寫功課／美安班學生的安親／課輔收費率，**對學生有利**。

**特殊折扣優先權不受影響**（`homeworkOverwriteApplies` 的 `!hasSpecialDiscount` 條件移除後，特殊折扣仍是最高優先）。#124 的裁示結論不變，但該 issue 所處理的覆蓋路徑將不存在——實作時應一併評估是否 close as fixed-by-#112。

**`isEnrolled` 保留**（§0.2）：它是學生視角的「是否報名安親／課輔」，管天數計算的適用性與顯示，不參與課程學費折扣判定。使用處：`billing-calculator.ts:468-472`、`care-days.ts:65,72`、`roster-changes.ts:217-218`。

**依 CLAUDE.md §2**，此為計算語意變更，須建立新 ruleSet 版本（現行正式軌 `erp-tag-v3`），舊 run 結果不可變。

### 3.5 重複報名提示

維持現有單一 `DUPLICATE_SUBJECT_ENROLLMENT` 與四個並列類別（`web/src/domain/billing/issues-detector.ts:41-52`）。其條件互斥已驗證：`careTokens` 走 `category==='care'`、`fixedFiveNoneTokens` 走 `category==='none' && fixedFiveDays`，同一班不可能同時落入兩組。新設計下只需把 `fixedFiveDays` 換成新欄位。**不合併、不新增提示。**

依 §0.4，該提示在真實資料上應極少觸發；保留它作資料異常的防孤。

### 3.6 UI

課表設定頁以**分頁籤**呈現，資料模型仍是同一份（改班名、合併衝突、班名搜尋、Excel 匯出入的邏輯不因分頁而分叉）：

```
┌ [非安親課輔班] ← 使用者打開預設顯示此頁
│  班級名稱｜列入多科折扣｜不計扣天｜星期｜起｜迄｜老師
└ [安親課輔班]  ← 第二順位
   班級名稱｜列入多科折扣｜固定 5 天｜老師   ← 不輸入上課時間與星期
```

- **新增入口為「新增班級」**（非「新增時段」）：安親課輔班不輸入上課時間，無法從「新增時段」流程生出。
- 安親課輔班的班級在草稿中必須落成 **`sessions: []`**（不產生佔位列），依 §2.6 佔位列會產生 `SCHEDULE_INCOMPLETE`。
- 安親課輔班的「固定 5 天」**預設不勾**，與所有班級一致（§3.3）。

### 3.7 安親課輔班的畫面狀態（**待 operator 裁決**）

依 §2.6，使用者新增一班安親課輔班時會顯示「待補」並出 `SCHEDULE_EMPTY`。兩個選項：

- **(a) 新增專門狀態**（如「此班不輸入上課時間」），該類班不發問題警示 —— **本 spec 建議採此**
- **(b) 接受現狀**，記錄為預期行為

**計算層不受影響**：`draftToScheduleOverride`（`web/src/adapters/sqlite/settings-repository.ts:198-218`）對空 sessions 是 `map.set(baseName, [])`，`resolveClassSessions`（`billing-calculator.ts:123-128`）讀到空陣列即回 `schedule_empty`、**不會退回 seed 課表**。因此安親課輔班落成 `sessions: []` 後，其扣天貢獻仍是 0（與 §2.1 一致）。

### 3.8 防呆

把有時段的班設為安親課輔班類別時，顯示確認並列出「該班時段將不再進入扣天計算」（依 §2.3）。**不禁止**把寫功課／美安設為安親課輔班（§2.4 實測無害）。

切換課程類型為不可逆操作（清空欄位），採確認式而非即時清空。不另建 undo——`handleDiscard → resetDraft`（`web/src/components/settings-editor.tsx:767-778,781-784`）已完整還原 rows／aliases／manualAttrs／restoredAutoNames／preview／upgradeConfirmed。

### 3.9 資料遷移

- **已儲存的 `fixedFiveDays` 值原樣保留**為新欄位的值，不做轉換。手動值（`fixedSource==='manual'`）維持手動語意。
- 依 [03](./03-architecture-api.md) §5.2.3 第 3 點，新設定快照只寫手動覆寫的值與來源，**自動項省略欄位**。因此既有草稿中未手動設定的班級，該欄位為 `undefined`，讀取時落到新預設（`false`，§3.3）。
- seed 的 8 個輔導班現行 auto 值經實測為 `false`（`detectFixedFiveDays` 不認輔導），與新預設一致。

### 3.10 「固定 5 天」需要 manual/auto 來源與「恢復自動」

新欄位須與既有行為一致：區分 `manual`／`auto` 來源、提供「恢復自動」、手動值隨班改名帶走（[06](./06-handoff-decisions.md) D37 1b、D40 Q9）。[03](./03-architecture-api.md) §5.2.3 第 3 點要求新欄位遵循同一邊界。
