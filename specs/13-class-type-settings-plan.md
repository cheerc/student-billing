# 13 課程類型分類與課表設定重構 Plan（#112）

日期：2026-10-18。依據：operator 2026-10-18 對話裁示、Lane A／Lane B 研究報告（本 session）、[02](./02-calculation-rules.md) §9、[09](./09-ui-workflow-redesign-spec.md) §3、[06](./06-handoff-decisions.md) D37／D40。狀態：**spec 草稿，實作未開始**。

本檔是**行為契約**（要做成什麼、遵守什麼），不是執行計畫（tasks 與順序）。實作計畫待 spec 經 dual review 通過後另寫。

## 0. 商業需求（operator 2026-10-18 對話原文依據）

以下四點是本 spec 的根基，**任何實作或 review 與此衝突即為錯誤**，不需回頭查程式碼：

1. **安親課輔班永遠一週五天**。天數固定 5 天，不同的天數都是從計算扣天算出來的。
2. **「不計扣天」的意思**：安親班、課輔班、輔導班，以及寫功課班、美安班，都是一週上五天。這五天的課程有些會跟數學課或美語課時間重疊，造成衝堂，需要扣除衝堂天數以避免重複收費。**但有些班級不列入衝堂扣費，所以固定是五天，因此「不計扣天」**。
3. **課程規劃分類**：「寫功課」「美安」是固定五天、不會被扣除天數的班級（商業需求）。安親班／課輔班／輔導班同樣是一週五天。數學班、美語班、作文班、國文班等都是**按堂計費**，一週可能一堂或兩堂，**不可能是一週固定五天**。
4. **輔導與寫功課／美安不會同時報名**。同一學生在「安親課輔班」類別只會報名一個班。

## 1. 問題

現行課表設定的每一列都要求輸入星期與上課起迄時間（[09](./09-ui-workflow-redesign-spec.md) §3「五個編輯欄」），且每個班都出現「天數固定 5 天」checkbox。但：

- 安親課輔班的星期與起迄**沒有計算意義**——系統已有固定窗口（安親 週一–週五 13:00–16:00、課輔 週一–週五 16:30–19:30，`web/src/domain/schedules/overlap-calculator.ts:9-12`），輔導班的時段從不進入扣天公式。
- 「天數固定 5 天」對多數班級是**用不到的特定需求**（operator 語），因為只有寫功課／美安才是真正需要它、而它們又不在折扣計算內的班。

#112 的原始描述（只對含關鍵字班級出現 checkbox）與 operator 的實際需求（依課程類別決定需要哪些欄位）**判定鍵不同**；本 spec 以 **§0 的商業需求**為準，#112 原始描述視為同一目標的較早、較窄版本。

## 2. 已證實的現況（Lane A／Lane B 研究，本 session 實測）

所有結論皆由實際執行的探針取得，非讀碼推論。

### 2.1 輔導班的時段完全不影響任何計算值

候選集合在 v3 以 `category==='math'|'english'` 篩選（`web/src/domain/billing/billing-calculator.ts:259,349`），`care`／`none` 進不去。實測（固定完整 classSettings 與 scheduleOverride，只改一個 `國小輔導-五年級` 班的 sessions）：輔導班「課輔窗口整段重疊的時段」vs「無時段」→ **IDENTICAL**（`rates` 9500、課輔 3.5、`issues` 空）。

### 2.2 「天數固定 5 天」有兩個作用，不只一個

| 作用 | 位置 | 實測 |
|---|---|---|
| 安親／課輔收費天數的地板 `max(..., 5)` | `web/src/domain/billing/care-days.ts:32,49` | 輔導班誤勾 → 課輔 3.5 變 **5** |
| 安親／課輔**適用率**變 10000 bps | `web/src/domain/billing/discount-rules.ts:186`（`homeworkOverwriteApplies`）→ `billing-calculator.ts:504-509` | 同上 → 9500 變 **10000** |

副作用已實測：輔導班誤勾該旗標會讓 `tierComparisons` **每一列由 `match` 翻成 `mismatch`**（ERP 登記 3.5 vs 計算 5）。這是 D17 最需要防的「掩蓋不一致」。

### 2.3 數學／美語班的時段確實進公式

實測（grade 4、輔導班＋數學班，數學週三 17:00–19:00 落在課輔窗口）：

```
數學班有時段 → 課輔 4、適用率 9500
數學班無時段 → 課輔 5、適用率 9500     → DIFFERENT
```

推論（**待 review 驗證**）：若允許把數學／美語班設為「免輸入時段」，該生天數會由 4 靜默跳成 5，收費金額隨之上升，使用者未下任何指令。

### 2.4 寫功課／美安班的時段不進公式

實測（寫功課／美安 有時段 vs 無時段）→ **IDENTICAL**（課輔 5、適用率 10000）。故「這兩類要不要排課」在數值上無差別。

### 2.5 分類自動偵測的邊界

實測 `detectClassCategory`：

```
美安 / 美安-三年級        category=none  fixedFive=true
國小輔導-美安              category=care  fixedFive=true
寫功課 / 寫功課-一A        category=none  fixedFive=true
國小輔導-四年級 / 安親班 / 課輔-五年級  category=care  fixedFive=false
作文-作文班 / 國文-小五 / 交通車 / 正音班  category=none  fixedFive=false
兒童美語-Gino              category=english
國小數學-四A               category=math
```

`CARE_WORDS = ['國小輔導','安親','課輔']`（`web/src/domain/classification/class-category.ts:24`）**不含「美安」**。因此**不能**用 `detectClassCategory(班名)==='care'` 當作「安親課輔班」的 auto 規則——它會漏掉寫功課與美安，而那兩類依 §0.3 確實屬安親課輔班。

### 2.6 「共用窗口」狀態不是機制，是偶然

`web/src/application/schedule-preview.ts:135-140` 的 `SHARED_WINDOW_CLASSES` 是**以班名靜態比對 seed JSON** 建出的集合，不是由草稿屬性推出。實測三情境：

| 草稿形狀 | 班狀態 | 問題碼 |
|---|---|---|
| seed 原班名（8 個 `國小輔導-*`），`sessions: []` | `shared_window` | 無 |
| 原班名，佔位列 | `shared_window` | 無 |
| **新班名**（不在 seed），`sessions: []` | `missing_time` | `SCHEDULE_EMPTY` |
| 新班名，佔位列 | `incomplete` | `SCHEDULE_INCOMPLETE` |

推論（**待 review 驗證**）：使用者新增一班輔導班時會看到「待補」與問題警示，而那是他選擇的型態、不是漏填。

## 3. 設計

### 3.1 課程類型（可擴充框架）

新增班級層設定「課程類型」，預設兩種：

| 類型 | 需要輸入時段 | 專屬欄位 |
|---|---|---|
| **非安親課輔班** | 是（逐列輸入星期、起、迄、老師） | **不計扣天**（逐列） |
| **安親課輔班** | **否**（只填班級名稱、老師） | **固定 5 天**（班級層） |

- 兩種專屬欄位**互斥**：各類別只顯示自己適用的欄位。領域模型上兩欄並存，UI 上不並列。
- 框架設計為可擴充：新增類別時，該類別「需要哪些欄位」隨類別定義宣告，不需改動其他類別的欄位。
- **不綁現有的 `category`（列入多科折扣）**。理由：[06](./06-handoff-decisions.md) D37 與 [02](./02-calculation-rules.md) §9.1 明文寫「類別與固定 5 天互不推導」，且 §3.2 顯示兩者語意正交。
- 自動偵測規則（**提案，待 review 驗證 §2.5 的邊界**）：班名含「國小輔導」「安親」「課輔」「寫功課」「美安」任一 → 安親課輔班；其餘 → 非安親課輔班。**只看班名的自動偵測，不讀已儲存的 `category` 欄位。**

### 3.2 兩個專屬欄位的語意（實測證明不可合併）

| 欄位 | 類別 | 作用對象 | 實測區別 |
|---|---|---|---|
| **固定 5 天** | 安親課輔班 | 該學生報名此班 → 天數地板 5 | 有額外扣天標籤時仍為 **5** |
| **不計扣天** | 非安親課輔班 | 該班的該一堂 → 該堂不算扣天 | 有額外扣天標籤時為 **3** |

決定性實測（grade 4、輔導班＋數學班，數學班時段落在課輔窗口）：

```
無額外扣天標籤：
  A 輔導班勾「固定 5 天」      → 5 天
  B 數學班所有時段勾「不計扣天」 → 5 天      ← 表面上相同
有「安課額外扣 2 天」標籤：
  A 輔導班勾「固定 5 天」      → 5 天
  B 數學班所有時段勾「不計扣天」 → 3 天      ← 不同
```

**結論：兩者不可合併、不可互相取代。**「固定 5 天」是整個天數的絕對地板；「不計扣天」只讓特定時段不參與扣天計算，其他扣天管道照跑。

（附帶：這兩者與「安課額外扣天」的先後順序存在規格矛盾，已另開 #147，不在本 spec 範圍。）

### 3.3 「固定 5 天」的預設值與可覆寫性

- 預設勾選（「是」），**任何安親課輔班都可取消勾選**。
- **不因班名而鎖死**。§2.5 顯示「寫功課／美安實測不可取消」，但那是**時段不進公式的結果**，不是規則。任何開在安親課輔班類的班（包括名為「1234班」的班）都應能自由決定要不要計扣天（operator 2026-10-18 明示）。

### 3.4 「不計扣天」不影響適用率

「列入多科折扣」決定適用率，「固定 5 天」／「不計扣天」決定天數，兩者正交：

| 學生報名的班 | 固定 5 天 | 列入多科折扣 | 適用率來源 |
|---|---|---|---|
| 輔導班 | 通常勾選 | 安親課輔 | 輔導班的設定 |
| 寫功課／美安班 | 勾選 | 不列入 | 不列入 → 不計算 |
| 交通車／作文班 | 不適用 | 不列入 | 不列入 → 不計算 |

「特殊折扣」標籤為最高優先權，直接取代計算值（已實證現行優先權仍在：`discount-rules.ts:186` 的 `homeworkOverwriteApplies = hasHomeworkOrMeian && !hasSpecialDiscount`）。

**本 spec 不改變 §2.2 現行的適用率行為**（寫功課／美安仍使安親／課輔適用率變 100%）。理由：operator 未就此裁示，且依 §0.4 輔導與寫功課／美安不同時報名，該 100% 只作用於不報安親課輔的學生（實測 `isEnrolled=false`）。若要拆分，屬 #124／#147 的規則變更範圍。

### 3.5 重複報名提示

維持現有單一 `DUPLICATE_SUBJECT_ENROLLMENT` 與四個並列類別（`web/src/domain/billing/issues-detector.ts:41-52`）。實測其條件互斥：`careTokens` 走 `category==='care'`、`fixedFiveNoneTokens` 走 `category==='none' && fixedFiveDays`，同一班不會同時進兩組。新設計下只需把 `fixedFiveDays` 換成新欄位、條件改為「固定 5 天且不列入多科折扣」。**不合併、不新增提示。**

依 §0.4，真實資料上該提示應極少觸發；保留它是防孤（資料異常時有用），不視為主要防線。

### 3.6 UI

課表設定頁以**分頁籤**呈現，資料模型仍是同一份（改班名、合併衝突、班名搜尋、Excel 匯出入的邏輯不因分頁而分叉）：

```
┌ [非安親課輔班] ← 使用者打開預設顯示此頁
│  班級名稱｜列入多科折扣｜不計扣天｜星期｜起｜迄｜老師
└ [安親課輔班]  ← 第二順位
   班級名稱｜列入多科折扣｜固定 5 天｜老師      ← 無星期／起迄欄
```

- **新增入口為「新增班級」**（非「新增時段」）：安親課輔班不輸入時段，因此不能從「新增時段」流程生出。新增班級 → 選類型 → 安親課輔班直接儲存；非安親課輔班再逐一新增時段。
- 安親課輔班的班級在草稿中必須落成 **`sessions: []`**（不產生佔位列），依 §2.6 佔位列會產生 `SCHEDULE_INCOMPLETE`。

### 3.7 安親課輔班的畫面狀態（**待 operator 裁決**）

依 §2.6，新建的輔導班會顯示「待補」並出 `SCHEDULE_EMPTY`／`SCHEDULE_INCOMPLETE`。兩個選項：

- **(a) 新增專門狀態**（如「不排課」），該類型態不發問題警示 —— **本 spec 建議採此**
- **(b) 接受現狀**，在文件中記錄為預期行為

**若採 (a) 未指定實作方式**，需明確：`schedule-preview.ts:135-140` 的 `SHARED_WINDOW_CLASSES` 改由草稿的課程類型推導（而非 seed 班名比對），該類班級的 `aggregateStatus` 回新狀態，且 `:267,297` 的問題判斷排除此型態。

### 3.8 防呆

把有時段的班設為安親課輔班型態時，顯示確認並列出「該班時段將不再進入扣天計算」（§2.3：數學／美語班會靜默歸零扣天、天數上升）。**不禁止**把寫功課／美安設為安親課輔班（§2.4 實測無害）。

切換類型為不可逆操作（清空欄位），採確認式而非即時清空。不另建 undo——`handleDiscard → resetDraft`（`web/src/components/settings-editor.tsx:767-778`）已完整還原。

### 3.9 既有資料遷移

已儲存的 `fixedFiveDays=true` 只會出現在寫功課／美安班（seed 的 8 個輔導班本來就是 `false`）。遷移為「課程類型＝安親課輔班」＋「固定 5 天＝是」，數值不變。

**待確認**：若有人在輔導班上手動勾過「天數固定 5 天」，遷移不改變其值（仍是 true），但該值在 auto 規則下會讓輔導班的 auto 判定與手動值分離。需決策此情形是否顯示警告。

### 3.10 計算端

**`web/src/domain/billing/care-days.ts` 完全不動。**本 spec 不改變任何計算結果：

- 「固定 5 天」仍走既有的 `max(..., 5)` 地板
- 「不計扣天」仍走既有的逐列 `skipDeduction` 過濾
- 計算端只需讀取新的班級層欄位取代 `fixedFiveDays`，其語意等價

變更限定在：課程類型欄位（domain + contracts + snapshot）、UI 分頁與欄位、欄位命名與顯示、資料遷移。
