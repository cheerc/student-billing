第一稿曾提 dual review（PR #149），兩位 reviewer 均裁 REJECTED。本稿修正了他們指出的事實錯誤，並依 operator 隨後的裁示重寫 §0／§3.2／§3.3——**特別是移除了第一稿的「依班名自動決定預設值」設計**，那是第一稿擅自加入、operator 明確否決的內容。

## 0. 商業需求（operator 2026-10-18 對話依據）

以下四點是本 spec 的根基，**任何實作或 review 與此衝突即為錯誤**：

1. **安親課輔班的基礎天數是 5 天，但衝堂要扣天。**五天是**基數**不是上限。數學班或美語班的時段與安親課輔班重疊就是衝堂，需要扣除衝堂天數以避免重複收費。**有些班級特殊、不列入衝堂扣費，所以需要一個旗標讓它們維持 5 天。這個旗標是使用者端的設定，不是系統判斷的。**
2. **「不計扣天」與「固定 5 天」是同一件事的兩種切入角度。**兩者處理的都是同一個問題：「此班安親課輔到底要算幾天」。差別只在作用對象——安親課輔班在**班級層級**需要它（「固定 5 天」），非安親課輔班在**每一堂**需要它（「不計扣天」，因為那些班本來就在算扣天）。
3. **課程規劃分類**：「寫功課」「美安」是固定五天、不會被扣除天數的班級（商業需求）。數學班、美語班、作文班、國文班等都是**按堂計費**，一週可能一堂或兩堂，**不可能是一週固定五天**。
4. **輔導與寫功課／美安不會同時報名**。同一學生在「安親課輔班」類別只會報名一個班。

**第一稿的錯誤（已移除）**：第一稿 §0 曾把第 1 點寫成「安親課輔班永遠是 5 天，不因衝堂扣天」，並據此推導「不計扣天 = 固定 5 天」是系統應自動設定的預設。operator 明確更正：**衝堂本來就要扣天，五天只是基數；旗標是給少數班級的特例用的。**

## 1. 問題

現行課表設定的每一列都要求輸入星期與上課起迄時間（[09](./09-ui-workflow-redesign-spec.md) §3「五個編輯欄」），且每個班都出現「天數固定 5 天」checkbox（`web/src/components/settings/schedule-grid.tsx:431`）。但：

- 安親課輔班的星期與起迄**沒有計算意義**——系統已有固定窗口（安親 週一–週五 13:00–16:00、課輔 週一–週五 16:30–19:30，`web/src/domain/schedules/overlap-calculator.ts:7-12`）。輔導班的時段從不進入扣天公式（§2.1）。
- 「固定 5 天」這個旗標**只有少數班級需要**，但它出現在每一班，且現行的自動偵測（依班名含「寫功課」「美安」）是一組會隨班名改變而漂移的 hard code（§3.3）。

#112 的原始描述（只對含關鍵字班級出現 checkbox）與 operator 的實際需求（依課程類別決定需要哪些欄位、旗標由使用者設定）判定鍵不同；本 spec 以 §0 為準。

## 2. 已證實的現況

所有數據皆由實際執行的探針取得。標「推論」者未經實測。

### 2.1 輔導班的時段完全不影響任何計算值

v3 的扣天候選以 `category==='math'|'english'` 篩選（`web/src/domain/billing/billing-calculator.ts:259,349`），`care`／`none` 進不去。實測（完整 classSettings 與 scheduleOverride，只改一個 `國小輔導-五年級` 班的 sessions，含整段落課輔窗口的時段 vs 無時段）：**IDENTICAL**——課輔天數 3.5、適用率 9500、`issues` 空。

*註*：9500 這個值來自「科數效應」（輔導＋數學＝2 科 → 基本折扣 9500）。若不傳 classSettings，輔導班的 auto `fixedFiveDays=false` 仍不干擾，但讀者需知道這個歸因。

### 2.2 「固定 5 天」旗標的兩個作用

| 作用 | 位置 | 實測（輔導班誤勾該旗標） |
|---|---|---|
| 安親／課輔收費天數的地板 `max(..., 5)` | `web/src/domain/billing/care-days.ts:32,49` | 課輔 3.5 → **5** |
| 安親／課輔適用率變 10000 bps | `web/src/domain/billing/discount-rules.ts:186`（`homeworkOverwriteApplies`）→ `billing-calculator.ts:495-509` | 9500 → **10000** |

副作用：**受影響的班級那一列**由 `match` 翻成 `mismatch`（ERP 登記 3.5 vs 計算 5）。其他班級的列不變（無登記級距者維持 `not_applicable`）。

適用率的 10000 只對「該生讀安親課輔」者成立——`hasHomeworkOrMeian` 與 `isEnrolledAnqin/isEnrolledTutoring` 在 `billing-calculator.ts:464-474` 是**兩條獨立算式**。

### 2.3 數學／美語班的時段確實進公式

實測（grade 4、輔導班＋數學班，數學週三 17:00–19:00 落在課輔窗口）：

```
數學有時段 → 課輔 4、適用率 9500
數學無時段 → 課輔 5、適用率 9500     → DIFFERENT
```

（4 天為精確值：重疊 150 分 ÷ 180 = 0.833… → D24 進位 1.0 → 5−1=4。）

**推論，待驗證**：若允許把數學／美語班設為免輸入時段，該生天數會由 4 靜默跳成 5，收費金額隨之上升。

### 2.4 寫功課／美安班的時段不進公式

實測（寫功課／美安 有時段 vs 無時段）→ **IDENTICAL**（課輔 5、適用率 10000）。

### 2.5 分類自動偵測的邊界

實測 `detectClassCategory`（`web/src/domain/classification/class-category.ts:22-40`）：

```
美安 / 美安-三年級         category=none  detectFixedFiveDays=true
國小輔導-美安              category=care  detectFixedFiveDays=true
寫功課 / 寫功課-一A        category=none  detectFixedFiveDays=true
國小輔導-四年級 / 安親班 / 課輔-五年級  category=care  detectFixedFiveDays=false
作文-作文班 / 國文-小五 / 交通車 / 正音班  category=none  detectFixedFiveDays=false
兒童美語-Gino               category=english
國小數學-四A                category=math
```

`CARE_WORDS = ['國小輔導','安親','課輔']` **不含「美安」**，故 `detectClassCategory(班名)==='care'` 不能代表「安親課輔班」。**本 spec 不使用這個判斷**（見 §3.3）。

*第一稿在此節曾聲稱「49 班中有 11 班 auto 為 true，成因『美安』是跨字元子字串」——該主張經查證不成立：seed 49 個班名中含「安」的班為 **0 個**。*

### 2.6 「共用窗口」狀態不是機制，是偶然

`web/src/application/schedule-preview.ts:136-140` 的 `SHARED_WINDOW_CLASSES` 是**以班名靜態比對 seed JSON**（`source==='care_window'` 的 8 個 `國小輔導-*`）建出的集合。實測四情境：

| 草稿形狀 | 班狀態 | 問題碼 |
|---|---|---|
| seed 班名，`sessions: []` | `shared_window` | 無 |
| seed 班名，佔位列 | `shared_window` | 無 |
| **新班名**，`sessions: []` | `missing_time` | `SCHEDULE_EMPTY` |
| 新班名，佔位列 | `incomplete` | `SCHEDULE_INCOMPLETE` |

**推論，待驗證**：使用者新增一班輔導班時會看到「待補」與問題警示，而那是他選擇的型態、不是漏填。

### 2.7 現行 auto 預設值（實測 `resolveClassAttributes`，無已儲存值時）

```
輔導班（國小輔導-四年級） → fixedFiveDays: false
寫功課班（寫功課-一A）   → fixedFiveDays: true
美安班（美安-三年級）     → fixedFiveDays: true
國小數學四A              → fixedFiveDays: false
```

## 3. 設計

### 3.1 課程類型（可擴充框架，只決定欄位存在）

新增班級層設定「課程類型」，由**使用者建立班級時選擇**，預設兩種：

| 類型 | 需要輸入時段 | 專屬欄位 |
|---|---|---|
| **非安親課輔班** | 是（逐列輸入星期、起、迄、老師） | **不計扣天**（逐列） |
| **安親課輔班** | **否**（只填班級名稱、老師） | **固定 5 天**（班級層） |

- 兩種專屬欄位**互斥**：各類別只顯示自己適用的欄位。
- 框架設計為可擴充：新增類別時，該類別需要哪些欄位隨類別定義宣告。
- **不綁現有的 `category`（列入多科折扣）**。理由：兩者語意正交（§3.4），且 [02](./02-calculation-rules.md) §9.1 L281 寫的是固定 5 天旗標「**與類別獨立**」。（第一稿引作「互不推導」——該字串不存在於 D37 與 02 §9.1，只出現在 `web/src/domain/classification/class-attributes.ts:5` 的實作註解。）

**風險（需實作注意）**：「課程類型」是第二個可獨立於 `category` 手動覆寫的持久化維度，與 #113／#122 剛修復的「兩欄各自手動覆寫、快照與名稱映射漂移」屬**同構的失敗模式**。實作時必須讓兩者的一致性在畫面上可見，不得任其靜默漂移。

### 3.2 兩個專屬欄位是同一件事的兩種切入

| 欄位 | 類別 | 層級 | 作用對象 |
|---|---|---|---|
| **固定 5 天** | 安親課輔班 | 班級 | 該生報名此班 → 此班不列入衝堂扣費，天數維持 5 |
| **不計扣天** | 非安親課輔班 | 每一堂 | 該班的該一堂 → 該堂不參與扣天計算 |

兩者處理的問題相同：「此班安親課輔到底要算幾天」。分列兩欄只是因為作用層級不同。

*第一稿曾以「有額外扣天標籤時 A=5、B=3」論證兩者不可合併。該論證是循環的——它依賴 `care-days.ts` 現行把固定 5 天地板放在額外扣天**內側**的行為，而那正是 #147 正在修正的缺陷。修正後兩者等價。本稿移除該論證。*

### 3.3 預設值一律為 false，移除班名 auto 規則

- **所有班級的「固定 5 天」預設一律不勾**（`false`）。
- **移除**現行依班名含「寫功課」／「美安」的自動偵測（`web/src/domain/classification/class-category.ts:34-36` 的 `detectFixedFiveDays`）。
- **不新增任何替代的 auto 規則。**寫功課班與美安班要固定 5 天，由使用者在 UI 手動勾選。

**行為變更（需明確記錄）**：寫功課班與美安班的預設值由 `true` 改為 `false`。這些班的學生天數會改變——依 §0.1，旗標的存在意義就是切換天數，不勾當然會變。這是 operator 明確接受的預期行為。

**理由**：現行 auto 規則是「依班名判斷」，班名一改規則就漂移。operator 2026-10-18 裁示：「全部簡單化處理，就是預設那個欄位是 null/false 之類的，建立班級的事情是使用者做的，不是要系統寫死的。」此舉同時消除 §2.5 記錄的 hard code（全面清理見 #148）。

### 3.4 「固定 5 天」與「不計扣天」不影響適用率

「列入多科折扣」決定適用率，「固定 5 天」／「不計扣天」決定天數，兩者正交：

| 學生報名的班 | 固定 5 天 | 列入多科折扣 | 適用率來源 |
|---|---|---|---|
| 輔導班 | 使用者設定 | 安親課輔 | 輔導班的設定 |
| 寫功課／美安班 | 使用者設定 | 不列入 | 不列入 → 不計算 |
| 交通車／作文班 | 不適用 | 不列入 | 不列入 → 不計算 |

「特殊折扣」標籤為最高優先權（`discount-rules.ts:186` 的 `homeworkOverwriteApplies = hasHomeworkOrMeian && !hasSpecialDiscount`）。

**本 spec 不改變 §2.2 現行的適用率行為**（固定 5 天旗標仍使安親／課輔適用率變 100%）。該行為屬既有規則（[02](./02-calculation-rules.md) §9.4），若要拆分需另案裁示。

*第一稿曾以「輔導與寫功課不同時報名」為由聲稱本 spec 不改變適用率。該免責不成立：`isEnrolled` 與 `hasHomeworkOrMeian` 是兩條獨立算式。本稿的結論正確，但理由是「本 spec 不動該規則」，而非「影響面小」。*

### 3.5 重複報名提示

維持現有單一 `DUPLICATE_SUBJECT_ENROLLMENT` 與四個並列類別（`web/src/domain/billing/issues-detector.ts:41-52`）。其條件互斥已驗證：`careTokens` 走 `category==='care'`、`fixedFiveNoneTokens` 走 `category==='none' && fixedFiveDays`，同一班不可能同時落入兩組。新設計下只需把 `fixedFiveDays` 換成新欄位。**不合併、不新增提示。**

依 §0.4，該提示在真實資料上應極少觸發；保留它作資料異常的防孤。

### 3.6 UI

課表設定頁以**分頁籤**呈現，資料模型仍是同一份（改班名、合併衝突、班名搜尋、Excel 匯出入的邏輯不因分頁而分叉）：

```
┌ [非安親課輔班] ← 使用者打開預設顯示此頁
│  班級名稱｜列入多科折扣｜不計扣天｜星期｜起｜迄｜老師
└ [安親課輔班]  ← 第二順位
   班級名稱｜列入多科折扣｜固定 5 天｜老師      ← 無星期／起迄欄
```

- **新增入口為「新增班級」**（非「新增時段」）：安親課輔班不輸入時段，無法從「新增時段」流程生出。
- 安親課輔班的班級在草稿中必須落成 **`sessions: []`**（不產生佔位列），依 §2.6 佔位列會產生 `SCHEDULE_INCOMPLETE`。
- 安親課輔班的「固定 5 天」**預設不勾**，與所有班級一致（§3.3）。

### 3.7 安親課輔班的畫面狀態（**待 operator 裁決**）

依 §2.6，新建的輔導班會顯示「待補」並出 `SCHEDULE_EMPTY`。兩個選項：

- **(a) 新增專門狀態**（如「不排課」），該類型態不發問題警示 —— **本 spec 建議採此**
- **(b) 接受現狀**，記錄為預期行為

**計算層不受影響**：`draftToScheduleOverride`（`web/src/adapters/sqlite/settings-repository.ts:198-218`）對空 sessions 是 `map.set(baseName, [])`，`resolveClassSessions`（`billing-calculator.ts:123-128`）讀到空陣列即回 `schedule_empty`、**不會退回 seed 課表**。因此輔導班遷移成 `sessions: []` 後，其扣天貢獻仍是 0（與 §2.1 一致）。

### 3.8 防呆

把有時段的班設為安親課輔班型態時，顯示確認並列出「該班時段將不再進入扣天計算」（依 §2.3）。**不禁止**把寫功課／美安設為安親課輔班（§2.4 實測無害）。

切換類型為不可逆操作（清空欄位），採確認式而非即時清空。不另建 undo——`handleDiscard → resetDraft`（`web/src/components/settings-editor.tsx:767-778,781-784`）已完整還原 rows／aliases／manualAttrs／restoredAutoNames／preview／upgradeConfirmed。

### 3.9 資料遷移

已儲存的 `fixedFiveDays` 值**原樣保留為新欄位的值**，不做任何轉換。遷移僅是把欄位重新命名／重新定位，不改值。

依 §2.7，seed 的 8 個輔導班現行 auto 值為 `false`；寫功課／美安班的 auto 值為 `true`，但 auto 值**不寫入草稿**（[03](./03-architecture-api.md) §5.2.3 第 3 點：新快照只寫手動覆寫的值與來源，自動項省略欄位），故既有草稿中這兩類班的 `fixedFiveDays` 欄位為 `undefined`。

*第一稿曾稱「seed 的 8 個輔導班本來就是 false」作為遷移等價的依據——該敘述經查證正確（`detectFixedFiveDays('國小輔導-一A')` 實測為 `false`）。第一稿另稱「49 班中有 11 班 auto 為 true」，該主張不成立（seed 班名含「安」者為 0 班）。*

### 3.10 「固定 5 天」需要 manual/auto 來源與「恢復自動」

新欄位須與既有行為一致：區分 `manual`／`auto` 來源、提供「恢復自動」、手動值隨班改名帶走（[06](./06-handoff-decisions.md) D37 1b、D40 Q9）。[03](./03-architecture-api.md) §5.2.3 第 3 點要求新欄位遵循同一邊界。

### 3.11 計算端

**`web/src/domain/billing/care-days.ts` 不動。**

但因 §3.3 改變了預設值，**寫功課班與美安班的計算結果會改變**（這些班的 auto `fixedFiveDays` 由 `true` 變 `false`）。這是 §3.3 明載的預期行為，非缺陷。

其餘計算路徑不變：「固定 5 天」仍走既有 `max(..., 5)` 地板、「不計扣天」仍走既有逐列 `skipDeduction` 過濾。
