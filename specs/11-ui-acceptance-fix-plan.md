1. 本班適用折扣的資料來源（02 §8 課程情境最終折扣）在 v2 read model 的取值方式與班級識別（classId／enrollmentKey）；B 使用 v2 值，D 後改讀 v3 時的切換點。

**S-D 節（D 開工前完成；未完成不派 D）**

2. **v3 入口切換矩陣**：空 DB、僅 ready、active v2、active v3、指定歷史 v1／v2／v3，各自 calculate／preview／apply／activate／import diff／deductions／query／detail 的 ruleSet 與設定快照來源。現況 `resolveFormalRuleSetVersion`（`schedule-preview.ts:172`）沿用 active run 版本、`executeCalculationRun` 預設 v2（`calculate-run.ts:59`）、`applySettings` 未帶版本（`apply-settings.ts:168`），單改預設值會造成預覽與套用版本不一致。
3. **首次從 v2 啟用 v3 的觸發動作與影響確認**：部署、讀取、migration 不得悄悄改 active；新結果必產生新 run，舊 run 值與分類不變。preview 固定目標 ruleSet、設定快照與完整草稿 hash，apply 用同一版本；類別、固定 5 天、自動／手動來源的變更都進 dirty、hash、TTL 與影響預覽。
4. **舊資料適配**：缺新欄位的舊設定 JSON 與新 schema 預設值的版本界線；不可讀的歷史不得以當前班名重新偵測後冒充歷史結果。
5. **共同解析來源**：query、detail、班級扣天、匯入異動明細共用同一套類別解析；除 UI `countedRawTokens` 外，`roster-changes.ts:155` 亦有 application 層「第一個數學／美語」鏡像，須一併處置。
6. **診斷標籤**：`calculate-run.ts:133` 目前把正式軌與 compat 的任何天數差標為 `NUMERIC_POLICY_DIFFERENCE`；v3 因類別或選班政策產生的差異須與 D24 數值差異分開標示。
7. **可解釋差異表（parity 依據）**：列出 v3（無人工覆寫）相對 v2 會改變的情境、規則原因、允許變動的欄位、合成案例與手算 expected。已知至少兩類：(i) 重複同類報名改取扣天最多；(ii) 一般輔導＋寫功課並存時不再誤減 1 科（例：一般輔導＋寫功課＋數學，v2 為 1 科、v3 為 2 科；D37 明定取代「寫功課減 1」）。S 須窮舉其他可能差異並交 operator 確認後才定稿。
8. **演算法與班級生命週期**：
   - 類別允許值與未知類別；偵測時點、偵測規則版本；自動／手動來源狀態與「恢復自動」。

### B1 查詢與選項（後端）

現況不足以承接表頭篩選：students route 把 query 轉成單值物件，同 key 多值會被覆蓋（`app/api/v1/runs/[runId]/students/route.ts:15`）；`queryRunStudents` 班級只查單一 `enrollmentKey／classId`（`query-students.ts:199`）；每頁預設 50、上限 200（`:172`）；部分白名單參數未落實條件；`hasClass` 以 `subject_count > 0` 判定（`:268`），是「有無折扣科數」而非「有無報名」。

- **可篩選欄位清單**（03 定稿）：每欄的值型別、傳輸格式（多值參數）、與既有單值參數的相容方式；逐欄確認後端條件真正生效。
- **三種狀態分開**：未設篩選（全部）／選了「(空白)」／取消全選後按確定（0 筆）；不得一律以空字串代表全部。
- **匹配語意**：複值欄（班級、問題類型）包含任一選值即匹配；跨欄 AND；人數依 personCode 去重，多班不相加。
- **options read model**：各欄選項取自指定 run 全部學生（不受頁碼限制），歷史 run 不讀最新設定；敏感欄位（姓名、代碼）不提供選項清單，只保留搜尋框；「全選搜尋結果」只加入搜尋命中者，**不清掉搜尋外既有的選取**。
- **一致性**：名單、統計、分頁 cursor 共用同一條件；條件改變即清 cursor；晚到回應不得覆蓋新條件的結果。
- **無課程（獨立語意，不重用 hasClass）**：以不可變 import 名冊的報名資料判定，**零 enrollment 才算無課程**；原始班級文字非空但解析失敗者不算無課程，保留問題提醒；只有寫功課、交通車或未列入折扣類別的班仍算有課程；保留的離班 token 仍算有課程，不依基準日另行過濾。全批無課程總數與當前條件下符合人數分開；匯入預覽與結果頁針對同一批資料。「不併入需確認」只代表無課程本身不新增 issue，該生若另有真實 issue 仍計入需確認。
- 驗收：UX25 後端部分、UX29 後端部分（§4）；integration 測試須含：超過 200 人且只出現在後頁的選項、同一學生同時屬於兩個所選班、OR＋AND、0／false／null、全部取消、確定／取消、切換 run／歷史、快速切換條件的晚到回應；無課程的空 enrollment、只有寫功課、只有交通車、有離班 token、未知班型、解析失敗、無課程但另有 issue，每案人數與點擊後名單一致。
- 效能：選項查詢與多值篩選依根 CLAUDE.md §8（篩選 ≤200 ms，477 人）量測並記錄。
