## 2. 資訊架構

延用藍／白／淺灰，寬版工作區＋固定簡潔側導覽，不新增儀表板卡片牆。

|入口|路由|用途|
|---|---|---|
|1 課表設定|/settings?tab=schedule|逐堂時段、老師、唯讀的安親／課輔窗口與重疊|
|2 匯入學生|/imports|選檔、確認名單、使用名單|
|3 核對結果|/?view=students 或 deductions|學生總表、班級扣天|

> **架構更新（D60）**：依 2026-10-27 Operator 拍板，系統採單一現況留存模型，全站收斂為上述 3 頁 UI。原 `/history` 次入口與歷史資料列表已全數移除。

數字表示順序，不強迫每次重走wizard。已有結果首頁直接到學生總表；初始首頁主動作「先確認課表」、次動作「匯入學生」。seed存在時說「已載入初始課表，請確認」，不假稱人員已確認。沒有學生也可查看班級扣天。

**「匯入」的業務語意與完成後導引（#83、#84 已實作；2026-10-04）**：

- **確認使用才算匯入（#83）**：「匯入」＝使用者按下「使用這份名單」。上傳／拖拉只看預覽就離開的名單不是匯入。因米豆奶每次匯出檔名固定，預覽不再出現「已經上傳過同名檔案」警示；同名判重仍在後端進行（重傳同檔須指向既有批次才能啟用），只是不呈現為使用者可見的警告。
- **完成畫面與 03 導引（#84）**：完成畫面只保留主 CTA「前往核對結果 →」並明說請前往「03 核對結果」；不提供「再匯入其他名單」——每次匯入都以新資料替換現行資料，該按鈕會造成可疊加的誤解（重新匯入的路徑就是側邊欄的 02）。匯入成功後側邊欄「03 核對結果」加上柔和靜態外框高亮（`.nav-item-highlight`），不使用脈衝／無限循環動畫；抵達 `/` 後自動消除且不復發。

課表設定兩頁籤：課表（預設）、班名對應（待處理數量）。班名對應未匯入時說「匯入名單後，可確認ERP班名」，不阻擋課表。結果頁兩頁籤：學生總表、班級扣天。頁首一個h1、一個主要動作；來源時間／檔名一行，核對基準日另外標明，不混稱月帳期。版本ID、規則碼及診斷JSON放資料資訊的技術摺疊區。

**結果頁導覽與「編輯此班課表」（11 B2 已實作；F04）**：結果頁的頁籤以網址`view`參數為準——`/?view=students`（預設）與`/?view=deductions`。直接開啟`/?view=deductions`、重新整理、瀏覽器返回，都停在該頁籤，不退回學生總表；使用者切換頁籤時網址以`replaceState`同步（不堆疊瀏覽器歷史）。班級扣天的「編輯此班課表」連結為`/settings?tab=schedule&class=<班名>`，帶**穩定班級識別**（B2以班名為識別，不依畫面排序或列序）：課表頁定位到該班，只列該班**全部**時段（進入時屬於該班的列會一直留在畫面上，編輯時改班名或新增該班時段都不會讓列消失），並有「顯示全部班級」可回到完整課表；找不到該班（例如已改名）時明說「課表中找不到班級」並顯示全部班級，不白屏。班級改名、拆班後識別鍵的行為，待[11](11-ui-acceptance-fix-plan.md) S-D 8分析定稿（D批）。兩個頁籤各自保留篩選條件（§5.1、§5.2）。驗收UX27。

## 3. 課表設定

### 3.1 版面與逐堂欄位

頁首 → 安親／課輔窗口摘要 → 班級搜尋／星期／在用或停用篩選 → 課表 → 固定底部操作列。

窗口**唯讀**：值來自ruleSet（現為安親週一至五13:00–16:00、課輔16:30–19:30，`web/src/domain/schedules/overlap-calculator.ts:9-12`），不提供「調整時段」入口或輸入框；星期依當前v2規則顯示，不在此增加可變星期政策。operator已決定安親／課輔窗口為固定時段、不會變動（D33，decision `d-20260929073427734990-0`），故不做窗口編輯、不做窗口dirty；現行計算也只讀ruleSet窗口、不讀draft窗口（§8.1）。示意稿的「調整時段」按鈕與此不符，見[design/README](design/README.md)。

課表設定以分頁籤呈現（`[非安親課輔班]` 預設開啟、`[安親課輔班]` 第二順位，兩頁籤欄位徹底分離，specs/14）：
- `[非安親課輔班]`：顯示逐時段不計扣天、星期、起迄時間、課程時長、安親/課輔窗口計算欄、操作（刪除時段），不顯示天數固定 5 天；
- `[安親課輔班]`（每班一列）：顯示班級名稱、列入多科折扣、天數固定 5 天、帶班老師、狀態（安親課輔班（不計時段））、操作（刪除班級），不顯示時段、不計扣天、時長與窗口欄；
- 新增班級支援選擇課程類型（預設跟隨當前開啟之頁籤）；依 Operator 2026-10-21 裁決（Issue #155），移除「轉為安親／非安親課輔班」按鈕與切換對話框，工作流回歸單純的「＋ 新增班級」與「✕ 刪除」。

五個編輯欄順序（非安親課輔班）：班級名稱、帶班老師、星期、上課時間（起）、上課時間（迄）。

**班級類別與固定 5 天（#157 已改寫；D37 1a、Q7-A、06 D53）**：兩項設定都已併入課表表格（#80），逐班以欄位呈現：

- 「列入多科折扣」為**五選一**：**（未設定）**／安親課輔班／數學班／美語班／不列入折扣。
  - **（未設定）**＝使用者**尚未指定**；「不列入折扣」＝使用者**明確**指定不列入。兩者在計算上相同（都不計科數），但**不得混為一談**——把未設定顯示成「不列入折扣」等於替使用者陳述一個他沒做過的決定（06 D53 Ruling 2）。
  - **類別一律由使用者決定，班名不參與判定**（#157 Ruling 1）。未指定者顯示「（未設定）」，由使用者補設定。
  - 使用者可隨時選回「（未設定）」以**撤回**指定；**沒有**「恢復自動／恢復預設值」按鈕（#157 Ruling 4：`auto` 來源已不存在，「依班名重新判定」沒有對應物）。
- 「天數固定 5 天」為獨立勾選（與類別互不推導），預設恆為不勾（#112、D52）。
- 每個控制項都有可讀標籤，鍵盤可達。
- 類別變更不影響時段，但一樣使頁面變成「有未儲存的變更」，並進完整影響預覽（人數、天數、已補科數、合計折扣）。
- **同名合併阻擋（Q9）**：兩個班級的所有時段列被改成同一個新班名，且兩者的類別／固定 5 天設定不同時，畫面顯示紅色警示說明衝突內容並停用「確認變更」，要求先選擇要保留的設定或改回不同班名；不靜默取其一。
- **跨類別別名提示（Q13）已於 #157 廢除**（06 D53 Ruling 4）：該提示的內容是「米豆奶班名與系統班名各自會被**自動偵測**成什麼類別，兩者不同」——自動偵測既已不存在，提示沒有可比較的對象，保留它只會是空殼。別名機制本身（把米豆奶班名對到系統班）不受影響，仍照常對應、預覽與儲存。
- **名單中尚未加入課表設定的班級（#157 PR-2）**：課表頁使用班名比對報告同一份 `report.rosterOnly` 顯示名冊有報名但目前沒有課表列的班名、學生數與報名筆數。［加入課表設定］帶入原班名並開啟一般新增班級流程；初始折扣類別為「（未設定）」且固定 5 天未勾，課程類型可由使用者選擇。此動作不建立 alias、不依班名推測類別或課程類型；候選已在草稿列中出現時隱藏，報告過期時停用操作，直到重新取得最新報告。

**升級確認（Q11；現況依 #159 PR-2 更新）**：active run 若為任一非 v4 版本（v1/v2/v3、compat 或無法辨識版本），設定頁顯示「改用新規則（v4）」勾選。未勾選時普通 preview/apply 與 activate/recalculate fail-closed，要求先明確授權升級；勾選後 schedule/settings preview 的 after 固定 v4，before 顯示持久化舊 Run 結果，不呼叫舊 calculator。確認後建立新的 v4 Run，舊 Run 完整保留；若缺少可讀取的 persisted before，preview fail-closed。空 DB 不顯示升級勾選，初次 Run 固定 v4。保留D25/D28逐列獨立改名，不改為只能整班改名。同名多列以細分隔分組；班名搜尋保留該班全部時段。新增時段在工具列，刪列在列尾選單、只改草稿且可取消；整班停用仍active=false。影響學生／別名的刪改在確認視窗呈現，不因有學生就禁止刪列。

右側只讀欄：課程時長（分）、安親重疊（分）、安親扣除（未取整／天）、課輔重疊（分）、課輔扣除（未取整／天）。兩個安親／課輔欄各自分組。單堂不能顯成已取整扣天。

顯示正扣除量（domain負數不改），原始天數最多小數3位，詳細值可在popover看；不可用顯示值計算。0顯示0；**缺時間顯「—」**（`aria-label="未設定時間"`，見下「缺時間的佔位列」），未知星期有警告；合法週六與週一到五窗口無交集才顯0，不把未知當已驗證無衝堂。

**缺時間的佔位列（#82 已實作；decision `d-20261004093019108435-11`）**：新增時段只有「班級名稱」必填，老師、星期、起迄都可留空——行政常先開班名、課表還在協調。佔位列的五個計算欄位（課程時長、安親重疊／扣除、課輔重疊／扣除）平靜顯示「—」，**不使用「待補」badge**：滿版重複的 badge 是視覺疲勞，「—」對齊 Excel 習慣。a11y 補償是該格帶 `aria-label="未設定時間"`，鍵盤與螢幕閱讀器使用者仍取得明確語意。「—」不阻擋草稿儲存（`gridRowsToClasses` 對不完整列不產 session），也不代表「沒有衝堂」——計算另有結果時照常顯示數字。本項**只改「缺時間」這一態**：「需確認」（未知／空白星期）與「共用」兩種狀態標記維持原樣，仍與其他狀態可區分。

**未知與空白星期（11 A 已實作；F01）**：

- 星期為**非空的非法值**：calculate對該列回row-level`unknown_weekday`；該列顯示可聚焦的「需確認」警告與可讀原因，不顯示成0或「無重疊」。合法週六仍顯示0。
- 星期為**空白**（或超過8字元）：原`CalculateSessionSchema.weekday`為`z.string().min(1).max(8)`（`web/src/contracts/settings.ts`），清空星期會使整個calculate回400。A採**路徑 (a)**：calculate接受空白與過長（上限64字元只擋不合理payload）的星期，回該列`unknown_weekday`與問題（空白時原因寫「沒有填星期」）；列與班級層級的狀態、問題清單由server一次算出（單一來源＝domain的`isUnknownWeekday`），畫面不另寫一套判斷。(b) 未採用（client端同源驗證會另寫一套班級層級狀態）。畫面行為：該列標「需確認」。
- **提交仍拒絕空白星期**：preview／apply維持只收完整合法時段（`SettingsDraft`）的既有契約，不因本項UI修正而放寬。
- **舊值立即失效**：清空星期或改成非法值後，該列先前算出的數字立即失效，顯示「—」或「需確認」，不得沿用舊數字。calculate回400或網路失敗時，同樣不得顯示為「無重疊」。
- 驗收UX07（修訂）：非空非法值與空字串各一個瀏覽器測試，另測calculate失敗；斷言警告可聚焦、原因可讀、舊值不冒充。

### 3.2 草稿與儲存

有效編輯後200–300ms debounce預覽，重用既有domain及設定轉換器，不複製公式到React。取消舊請求／requestKey保護，晚到回應不得覆蓋新草稿。底部顯「有未儲存的變更」，次動作「取消修改」、主動作「確認變更」。班級／老師／星期／起迄／停用／班名對應的任何編輯都要dirty，並使舊preview失效。**取消草稿**：dirty 時取消修改不受唯讀即時計算在途阻擋（calculating 不停用取消按鈕，pointerdown/up 間開始計算亦不吞掉取消）；取消後立即還原至 baseline 並清理離頁守衛與哨兵歷史；確認變更與儲存則仍受計算與提交 gate 保護。

課表預覽標「未儲存」，可展開「本班合計」看草稿總扣天；結果頁預設已儲存run，不靜默混入草稿。

確認視窗：修改班級／時段摘要與「無時段班級」數（§8.2.4）；有active學生顯**受影響去重人數**（天數、科數、合計折扣與課程學費折扣四種差異的 personCode **聯集去重**——同一人只計一次，不得相加；四者皆空時為 0；#112 PR-2 納入課程學費折扣差異 `courseRateDeltas`）、天數前後、拆班／停用／失效對應；無學生顯「尚未匯入學生」，學生影響為null，不能寫0當作驗過。主按鈕有學生為「儲存並更新結果」，無學生為「儲存課表」。只有此時提交。

成功短toast＋「下一步：匯入學生」或「查看核對結果」。失敗保留草稿與舊結果；409／過期說「資料已更新，請重新確認變更」，可重試。送出中disabled且冪等；離頁提醒見下段，不每改欄就跳modal。

**離頁提醒（11 C 已實作；D38 F07）**：課表有未儲存修改（dirty）時，下列站內離開入口一律跳確認，選項為「繼續編輯」（留在課表頁、草稿保留）與「捨棄修改」（丟棄草稿後離開）：側欄各頁、品牌／首頁連結、班級編輯入口、瀏覽器Back。**儲存成功後不再提醒**；沒有修改時不打擾。reload與關閉分頁以`beforeunload`觸發瀏覽器原生提醒（瀏覽器規定使用者對頁面有過互動才會出現；不要求自訂文案，驗收只驗有互動後會出現）。驗收UX31，測試須走實際的側欄導覽。

**11 C 現況——離頁守衛的做法與範圍**（`web/src/lib/unsaved-guard.ts`、`components/ui/use-unsaved-changes-guard.ts`、`components/settings/leave-confirm-dialog.tsx`）：

- **只在有未儲存修改時啟用**：`dirty`（課表時段或班名對應與已儲存版本不同）為真才安裝；儲存成功、按「取消修改」、或卸載就解除。已儲存的頁面、沒有修改的頁面、唯讀的歷史頁都沒有任何監聽或歷史紀錄。
- **站內連結（含側欄、品牌連結、班級編輯入口等任何連結）**：在window捕獲階段攔截同源連結的點擊；導向的網址（路徑＋查詢）和目前不同就先跳確認，網址完全相同（沒有要離開）不動作。這是通用做法，沒有逐一元件特判——日後任何新連結掛在課表頁都自動涵蓋。「班級編輯入口」（核對結果頁班級扣天的「編輯此班課表」）是**進入**課表頁的入口；驗收以「從它進入→改草稿→經站內連結離開會先確認→捨棄後再從它進入是乾淨的伺服器狀態」涵蓋。頁內的「顯示全部班級」只改網址參數（`replaceState`）、不離開課表頁，不跳確認。
- **瀏覽器Back（Forward）**：啟用時多推一筆同網址的哨兵歷史紀錄，Back先退到同一頁並被攔截，再補上哨兵，因此可以反覆攔截；「捨棄修改」以`history.go(-2)`回到使用者原本要去的那一頁。popstate由根版面在Next掛載前預先安裝的先手監聽器轉交（`leave-guard-registry.ts`），才能排在Next的處理器前面，連按兩次Back跳過哨兵也攔得住。儲存成功或取消修改後哨兵會退掉，Back一步就是上一頁。
- **確認視窗不累積、只導覽一次**：同一時間只保留一個待確認動作（連點連結、連按Back都只有一層視窗）；「捨棄修改」先解除守衛再導覽一次（先退掉哨兵再`router.push`），歷史紀錄只多一筆；離開後不留下`beforeunload`。Esc等同「繼續編輯」。
- **限制（如實記錄）**：(1) `beforeunload`的原生提醒只有在使用者對頁面有過互動（例如點過輸入框）後瀏覽器才會顯示，這是瀏覽器規定；(2) 跨文件的返回（例如重新整理後才產生的舊歷史紀錄，Back會做整頁載入）只能靠`beforeunload`提醒，無法自訂視窗；(3) 站外連結、直接改網址列、關閉分頁同樣只有瀏覽器原生提醒。

### 3.3 班名對應

呈現ERP班名、去重學生數、系統班級選擇、狀態。用「ERP班名 → 系統班級」，不顯alias/baseName。D32建議目標維持空白，由人員選擇；動態差集與已對齊隱藏保留，禁止模糊自動批准。區分「選現有班級」與「建立新班級」。本次未出現班級列在「系統有／本次名冊無」清單（預設展開，見下），不自動停用。

對應與課表同一草稿、同一次影響預覽／交易，保留改散與失效警告。數量標班名數，不與學生／報名筆數混用。

**班名比對報告（11 D1 已實作；D37第4點、[06 D40](06-handoff-decisions.md) Q12-b）**：「班名對應」頁籤最上方是「班名比對報告」區塊，兩份清單**並排、預設展開**（不收合、不需點擊）：

- 左「米豆奶有／系統無」：標題下一行「N 個班，影響 M 位學生」；每班列米豆奶班名與「學生數（筆數）」。M 是涵蓋的**不重複**學生數（同一人在多班只算 1）。
- 右「系統有／本次名冊無」：標題下一行「N 個班」；每班列系統班名、上一份名單該班的人數與備註（已停用；由哪些別名覆蓋）。人數是**上一份名單**（漂移參考）該班的不重複學生數，並註明來源（檔名、建立時間）；沒有上一份名單時不顯示人數，明說「沒有上一份名單可參考」，不寫 0。
- **別名不對稱**以文字說明：已建立別名對應的米豆奶班名在左邊算「已對應」；右邊只看名冊有沒有直接用該班名報名，所以只靠別名覆蓋、名冊沒有直接報名的系統班仍列在右邊並標出由哪些別名覆蓋。
- 「上一份名單」的規則：上一份現行名冊依成功 activate/apply 收據與 revision 序號追溯（[03 §5.2.4](03-architecture-api.md)；嚴禁以未啟用的 ready 批次或 timestamp 冒充）；檢視的名單不是現行名單且有現行名單→現行名單；檢視的名單就是現行名單→該現行 episode 之前一份現行名冊；無前份名冊時明說「沒有上一份名單可參考」；收據毀損或出現 gap 時 fail-closed 提示無法判定。
- 成功儲存別名或班級設定後，同頁之班名比對報告即時刷新，不需使用者手動重整頁面（[04 UX46](04-tdd-acceptance.md)）。刷新**維持畫面正在檢視的名單**（`?import=` 指定的另一批就刷新那一批，不跳成現行名單的報告）；沒有檢視中的名單就沒有報告可刷新。若儲存已成功、但重新取得報告失敗，該區**先自動重試 2 次**（約 1s、3s 間隔；任一次成功即正常顯示，不顯示錯誤畫面）；重試期間報告區顯示一行中性佔位「更新中…」（非錯誤樣式、無說明文字）並**不顯示儲存前的舊數字**——舊數字既不能當成目前設定的結果，也不該被用來確認班名；同時**候選表鎖定**，恢復後自動解鎖並以最新報告重建。重試皆失敗才顯示單行標示「無法取得最新的班名比對報告。」＋［重新載入］（**只重新取得報告一次、不自動重試**——自動重試只發生在「儲存後」那條序列）；［重新載入］再失敗則改為［重新整理頁面］，按下才整頁 reload——不自動整頁 reload、不跳確認視窗、不勸告重新匯入（[04 UX46](04-tdd-acceptance.md)；operator 裁決 `d-20261002162913018695-69`、語意凍結裁決 `d-20261004044745983486-3`：錯誤提示只給最短恢復路徑，不解釋原因）。只改草稿、取消、儲存失敗時報告不動（仍是已存設定的報告，不提早反映草稿）。
- 範圍：檢視的名單預設為現行名單（無則最新一批），網址 `?import=<批次 id>` 可指定另一批（尚未啟用的新上傳也可看，儲存設定仍以現行名單為準）；設定範圍為最新已儲存設定（尚無才是 seed）。歷史 run 的快照範圍由 `GET /api/v1/settings/class-name-report?runId=` 提供，快照缺失時回「無法判定」，畫面不猜。
- **D1 的報告不顯示「類別」**（類別是 D2 的設定與計算功能）。
- 報告下方保留既有「待確認米豆奶班名」可編輯表（建立對應）；原「本次名單未出現的班級」收合區由右清單取代。窄螢幕（≤720px）兩份清單改上下排列。

## 5. 核對結果

### 5.1 學生總表

**表頭篩選（11 B2 已實作；D36）**：取代原「班級→學生搜尋→需確認→更多篩選」的兩排篩選列。各欄表頭▾開啟可捲動的勾選清單，可輸入關鍵字過濾選項後複選。六點補強：

1. 選項的值宇宙取自**整個run**，不是只取當頁；依 D46，各欄計數套用其他欄已套用篩選（含選班、姓名搜尋），排除本欄自身條件。server 保留0人值，學生面板只隱藏未勾選0人值，已勾選0人值仍可取消且不被prune；歷史run不讀最新設定。姓名與人員代碼是敏感欄位，不提供選項清單；學生姓名維持搜尋框（`q`），不入URL。
2. 輸入關鍵字後可一鍵「全選搜尋結果」（只加入搜尋命中者，不清掉搜尋範圍外既有的選取），並提供「(空白)」選項。
3. 按「確定」才套用；「取消」保留原條件。
4. 表格上方顯示可逐一移除的已套用條件chips與「清除全部」；有篩選的欄位▾變色。
5. 同一欄的選項為OR、不同欄為AND；複值欄（所屬班級、問題類型）學生任一報名班／任一問題命中即列出。人數依personCode去重，多班不相加。
6. 「本班」字樣與本班適用折扣只在**恰好選一班**時出現；選多班顯示「已選 N 班，共 M 人」；未選班顯示「全部 N 人」（O03）。

三種狀態分開：未設篩選（全部）／選了「(空白)」／取消全選後按確定（0筆）；不得以空字串一律代表全部。查詢契約見[03 §5.1](03-architecture-api.md)。

**B2現況——面板語意與網址契約**：

- **面板**：面板內的勾選是草稿，按「確定」才套用，「取消」、Esc、點面板外都保留原條件。面板沒有任何勾選＝該欄未設篩選（全部）；先按「取消全選」再按「確定」＝0筆（`~none`，面板會提示「按『確定』會顯示 0 筆」）；勾選部分選項＝該欄OR。「全選搜尋結果」只加入目前搜尋命中的選項，搜尋範圍外既有的勾選保留。選項取自`GET /runs/{runId}/students?options=true`（整個run；不含姓名與代碼），依欄位排序：保留項目（「(空白)」、「班名無法解析」）在最上，其餘數值欄依數值、文字欄依字串；每個選項附依其他已套用條件計算的去重人數，等於把本欄改為該單值後的結果人數；學生選項重取使用abort／sequence避免舊回應覆蓋新計數。「(空白)」（`~blank`，所屬班級＝無課程）與「班名無法解析」（`~empty`，有報名但班名空）是兩個不同項目，皆不是空字串。
- **需確認欄**有兩個分區：「米豆奶天數比較」（天數不同／天數吻合）與「問題類型」（只顯示中文名稱；「(空白)」＝沒有待確認事項），兩個分區共用同一個確定／取消，各自OR、彼此AND。
- **已套用條件**顯示在表格上方：每個條件一顆可移除的chip（含姓名搜尋的chip），另有「清除全部」（同時清空姓名搜尋）；有條件的欄位▾變色（`data-filter-active`）。
- **網址**：`view`、`runId`與非個資條件寫在網址，各條件使用API參數名與03 §5.1的傳輸格式（重複key、`~blank`／`~empty`／`~none`、`~~`跳脫）——所屬班級`enrollmentKey`、年級`grade`、安親天數`anqinDays`、課輔天數`tutoringDays`、額外扣天`hasExtraDeduction`、合計折扣`baseDiscountBps`、本班適用折扣`applicableDiscountBps`、兄弟姊妹折扣`sibling`、特殊折扣`specialDiscount`、園內生`internalStudent`、米豆奶天數比較`tierMismatch`、問題類型`issueCode`；班級扣天頁籤的條件用`dClass`、`dTeacher`、`dStatus`。姓名搜尋`q`不入網址，頁內session保存（同一分頁返回或重新整理仍在）。網址帶有這份資料中已不存在的選值（例如run變更後）時，載入即自動移除並提示「已移除N個在這份資料中不存在的篩選值」，網址同步為移除後的條件與目前的run；網址條件無效（例如`hasExtraDeduction=maybe`）時忽略全部條件並提示，不出錯誤頁。
- **一致性**：名單、統計、分頁cursor共用同一條件；條件改變即清cursor；只採用最新一次查詢的回應，晚到的舊回應不得覆蓋新條件的結果；載入中保留舊表並標「更新中…下方仍是上一次的結果」。
- **保留的能力與UI入口**：既有API參數不刪。「已補科數」不提供篩選（`hasClass`是折扣科數，不是無課程判定）。**分校**沒有預設欄位，其UI入口**待operator確認**，本批（B2）不實作、不自行決定，API參數（多值OR）保留生效。
- **特殊折扣欄**顯示標籤上的特殊折扣（例如95折；沒有標籤為「—」）；課程適用率不再出現在此欄，改由恰選一班時的「本班適用折扣」欄顯示。

**移除「科別」篩選入口**（D36；operator：過度工程）：只移除UI入口，**不刪除既有API查詢參數**（agent可能使用）。其餘篩選能力保留並對應到欄位表頭：班級→所屬班級、年級→年級、天數＋careType→安親天數／課輔天數、額外扣天→額外扣天、基本率→合計折扣、課程適用率→本班適用折扣（僅恰選一班）、兄弟姊妹→兄弟姊妹折扣、特殊折扣→特殊折扣、園內生→園內生、問題類型與ERP比較→需確認。分校沒有預設欄位，其UI入口待B2與operator確認，在此之前API參數保留；不能為簡化而移除原能力。

**篩選面板可及性（11 B2 已實作）**：觸發鈕名稱為「{欄名}篩選」並有展開狀態（`aria-expanded`）；面板`role=dialog`、名稱為「{欄名}篩選面板」。鍵盤：Enter／Space開啟，焦點進入搜尋框；Tab順序為搜尋→全選搜尋結果→取消全選→各選項（Space勾選）→取消→確定，Tab在面板內循環不逸出；Esc關閉，關閉後焦點回到表頭按鈕。面板以portal掛在頁面最上層、fixed定位並夾在視窗內（下方不夠時翻到上方），sticky表頭或overflow不裁切；選項清單在面板內捲動，「取消」「確定」固定在面板底部，短視窗（768×600）仍看得見。run變更時，已不存在的選值自動移除並提示（見上）。驗收UX25。

**無課程提示（11 B1／B2 已實作；D38）**：人數列旁另設顯眼提示，顯示「無課程」人數——米豆奶名冊中沒有任何班級的學生——並以文字提示使用者至米豆奶辦理離籍；可點擊，點擊後篩出這些學生（等同所屬班級選「(空白)」）。獨立計數，**不併入「需確認」人數**；全批無課程總數與當前條件下符合人數分開顯示；匯入預覽同數（§4）。「無課程」只指零報名，與「離班標記」（token帶日期）是不同概念，不可混同；精確判定見[03 §5.1](03-architecture-api.md)。實作：人數行旁的「無課程 N 人 · 請至米豆奶辦理離籍」按鈕（N＝全批，`noCourseTotal`）；另有條件時再標「（目前條件內 K 人）」（`stats.filteredNoCourseCount`）；點擊＝所屬班級只選「(空白)」（其他欄條件保留）。匯入預覽與尚未使用名單頁的統計卡同樣標「無課程」，附相同提示與「只看無課程的學生」，人數與判定相同。

**本班適用折扣的類別來源（D2b 已實作；N-8 對齊；#112 起依規則版本分流）**：「本班適用折扣」欄在具快照能力的 run（v3、v4）依**該 run 的班級類別快照**（`run_class_categories`）判斷，而不是用班名做名稱映射：

- 快照由 server 於渲染核對結果頁時讀出並傳給學生總表（不把資料庫帶進瀏覽器）；查詢 key 是**名冊班名**（與快照的 `base_name`、與篩選選出的班名同源）。
- 固定 5 天對本班折扣的影響**隨規則版本不同**（#112）：`erp-tag-v3` 下固定 5 天的班（即使類別為「不列入折扣」）顯示 100%，不是「未設定」；**`erp-tag-v4` 起不再如此**，本班折扣完全由 `category` 決定，`none` 班（即使固定 5 天）顯示「未設定」。
- v1／v2 run 沒有快照，仍用名稱映射，行為與過往一致。
- 缺該班快照時顯示「未設定」（無法判定），不以當前班名猜測。
- 畫面以該 run 的 `ruleSetVersion` 傳入讀模型分流，不自行字面比較版本（02 §9A.3、03 §5.3.4）。

**Q14（舊 subject 欄位）**：D2 起 UI 不再顯示班級的舊 `subject`（科別）欄位；相容欄位仍在資料與 API 中保留，且不作計算依據。目前學生總表與明細皆未顯示該欄位。

**B2現況——人數行與本班適用折扣（UX28）**：人數行依所屬班級條件標範圍：未選班「全部 N 人」、恰選一個班級「本班 N 人」、選多班「已選 N 班，共 M 人」（M為聯集去重）；只選「(空白)」或「班名無法解析」時標「已選「…」，共 M 人」、取消全選時標「已取消全選，共 0 人」，這三種都不寫「本班」也沒有本班適用折扣欄。本班適用折扣欄排在合計折扣右側、不覆蓋基本率，值取自四個已持久化的學生層適用率欄位，班級類別沿用03 §5.1的暫定v2映射（`applicable-rate.ts`，SQL與畫面共用）：國小輔導依年級取安親（一、二年級）或課輔（三至六年級）、國小數學取數學、兒童美語取美語；未配置的班顯示「未設定」（不是100%），已配置但該生無法判定（例如年級未知）顯示「—」。本班適用折扣有自己的表頭篩選；不再恰選一班時，該條件自動移除並提示。

- **錯誤說明一律「白話主文＋可展開的『詳細資訊』」**（`ErrorNotice`；文案集中在`web/src/lib/user-messages.ts`）：主畫面只有白話與下一步，錯誤代碼與伺服器原始訊息（含HTTP狀態、例外訊息）預設收合。涵蓋：匯入上傳（損毀檔案＝D39 (3)；缺少必要欄位；重複人員代碼；加密、過大、找不到名單資料；連線中斷）、啟用名單、核對結果與名單的查詢失敗、課表「確認變更」的預覽與套用失敗。

- **問題類型**：總表「需確認」欄的徽章、明細抽屜的待確認事項都只顯示中文名稱與白話說明（`web/src/lib/issue-copy.ts`；資料層原始訊息可能含工程詞，歷史run也已存了舊訊息，所以畫面一律以「代碼→白話說明」呈現），代碼與原始訊息只在抽屜的「技術資訊」。抽屜的比對結果標籤不再帶英文（Match／Mismatch），「fallback」改為「暫以相容數值比較」。

### 日期與時間格式（11 C 已實作；D38 O02）

全站日期時間一律以Asia/Taipei顯示為`YYYY-MM-DD HH:mm`（匯入時間、課表儲存時間、核對橫幅等），不混用瀏覽器locale；核對基準日等純日期維持`YYYY-MM-DD`。驗收UX33。

**11 C 現況**：所有畫面都經`web/src/lib/datetime.ts`的`formatDateTime`（含課表頁狀態列的儲存時間、匯入頁「目前課表」的儲存時間；原本這兩處用瀏覽器`toLocale*String()`，會依瀏覽器語系與時區顯示成`9/30/2026, 3:04 PM`，且會造成伺服器與瀏覽器轉譯不一致的hydration錯誤）。課表儲存成功後，狀態列**立刻**顯示新的儲存時間（用套用回應的`appliedAt`），也一併更新目前版本，不必重新整理就能再次確認變更。**核對基準日的預設值是台北時間的今天**（`todayInTaipei`）：原本用UTC日期，台北凌晨0–8點會是前一天；匯入頁與首頁「使用這份名單」兩個啟用入口都改用它。

## 8. 必要API／持久化銜接

「現況」皆對照`66d6371`的`web/src`；本文件只定義目標契約，不修改程式。8.2.1、8.2.2、8.2.4是**既有缺陷**，非本次UI改版新增，但先課表流程會放大它們。

### 8.1 唯讀計算read model

新增application calculateSchedulePreview，重用overlap-calculator與相同設定轉換（draftToScheduleOverride，語意見8.2.4），v2明確帶sameWeekdayOnly。不要前端自算第二套。

**窗口唯讀**：窗口是ruleSet參數（`RuleSetOptions.anqinWindow／tutoringWindow`，`web/src/domain/schedules/overlap-calculator.ts:36-37`，預設常數`CARE_WINDOWS`同檔9-12）。現況`draftToScheduleOverride`只轉換sessions（`web/src/adapters/sqlite/settings-repository.ts:165-181`），draft的careWindows沒有進入計算。故read model一律用ruleSet窗口，回應帶`windows`供畫面唯讀顯示，不讀draft窗口，避免預覽與正式run不同源。`SettingsDraft.careWindows`仍是schema必填（`web/src/contracts/settings.ts:300-303`），UI一律帶ruleSet值；server收到不同值回400 INVALID_DRAFT，不靜默忽略。

建議POST /api/v1/settings/calculate：輸入draft（`CalculateDraft`，允許帶可選`rowId`，且`startMinutes`／`endMinutes`允許為null或end≤start的不完整列，`weekday`允許空白或過長〔≤64字元〕，回該列`unknown_weekday`，見§3.1）、requestKey（**不含ruleSetVersion**）；回requestKey、draftHash、ruleSetVersion、windows、rows、classes、issues。rows含rowId/classKey/durationMinutes、兩組overlapMinutes/rawDeduction/status；classes含兩組totalOverlapMinutes/raw/rounded/status/rowIds。rowId保持穩定（client帶來的原樣回傳，未帶才補序號），不完整列回null＋`missing_time`與`SCHEDULE_INCOMPLETE`問題；班級含不完整列時標為`incomplete`，扣天只計完整列；`draftHash`取去掉不完整列與rowId之「存檔等價draft」計算，確保與存檔時之preview `inputHash`完全同源；星期空白或過長的列存不了（settings/preview回400），同樣不入hash；此時hash對應移除這些列後的草稿，可能與該可存檔草稿的`inputHash`相同，不代表原草稿可提交，也不取代列狀態與問題。這個POST僅純計算，不建立preview／run、不寫DB，仍驗same-origin與payload限制。

**現行 `ruleSetVersion` 入口（#159 PR-2）**：server 新計算一律選 `erp-tag-v4`，client 不得指定。active 舊版不會沿用；未明確勾選 v4 upgrade 時 fail-closed。原 D1 resolver 選版說明留作歷史記錄，現在由 [03 §5.6](03-architecture-api.md) 覆蓋。

新增GET /api/v1/settings/deductions?runId=：指定run讀固定快照；無指定有active則active，無active才saved settings；回scope及版本，不寫DB。不可用最新課表補舊run。

### 8.2 activate與儲存的資料來源

**8.2.1 activate採最新已儲存設定（現況缺陷）**

現況：roster-view送出activate只帶expectedRevision／idempotencyKey／asOfDate（`web/src/components/roster-view.tsx:84-91`）；route只轉交asOfDate／scheduleVersionId／ruleSetVersion（`web/src/app/api/v1/imports/[previewId]/activate/route.ts:22-32`）；activateImport以此options呼叫executeCalculationRun（`activate-import.ts:112`），options沒有aliasMap／scheduleOverride（`web/src/application/calculate-run.ts:92-93,99-100`皆為undefined），scheduleVersionId預設`seed-v250922`（同檔28）。結果：「套用設定→匯入新名單→啟用」的新run計算退回seed課表、不套班名對應，且run.scheduleVersionId（同檔200）標成seed。D17要求照實呈現，這是靜默丟失人工設定。apply路徑則正確傳入（`web/src/application/apply-settings.ts:129-135`）。

目標契約：**每一次**activate，server於同一交易內解析最新已儲存settings version（`getLatestSettingsVersion`，取revision最大者，不依日期）：有則經draftToAliasMap／draftToScheduleOverride（同apply）計算，run.scheduleVersionId＝該version id；尚無任何已儲存設定才用seed（scheduleVersionId維持`seed-v250922`）。client傳入的scheduleVersionId一律忽略，冪等hash不含它。activate body 帶 `ruleSetVersion`（含 null）一律 400 `INVALID_REQUEST`，application 層也拒絕；新 Run 固定 v4。Active 舊版需先明確勾選 v4 upgrade，否則 fail-closed；舊成功 idempotency replay 仍先回原 response。activate與設定變更之間的競爭由revision CAS擋下。原 D1 resolver 版本沿用說明保留為歷史記錄；現況見[03 §5.6](03-architecture-api.md)，驗收見UX98。

`effectiveFrom／effectiveTo`現況只在apply寫入（`apply-settings.ts:121-122`），沒有任何選版或計算讀取，設定編輯器也無此欄；operator已決定窗口固定（D33），無需依日期選版，有效日期**不在範圍**：欄位保留於schema但不使用，本文件不描述、UI不提供有效日期能力；核對基準日asOfDate是既有概念（§2、§4），與有效日期無關。

**8.2.2 儲存的import由server決定**

現況：preview接受任意client importId（`settings/preview/route.ts:16-26`，`settings-preview.ts:117-120`只檢查該批有學生），apply把`active_state.active_import_id`設為preview.importId（`apply-settings.ts:140-142`）。client可傳非active的ready批次，儲存設定的同時把它啟用，等於繞過匯入頁activate的確認。

目標契約：preview／apply的import一律由server依`active_state`決定：有active→active import（with_students）；無active→settings_only，即使存在ready批次也不啟用它。契約刪除client的importId；過渡期若仍收到，僅做一致性檢查，與server決定值不符（含client以null繞過active、傳入非active批次）即以400／409拒絕，絕不採用client值。ready批次只能經匯入頁activate啟用（§4）。

**8.2.3 無學生儲存與migration**

沿用settings/preview與apply，mode由server判：settings_only／with_students。settings_only影響人數為null、apply只保存設定並遞增revision，runId=null、不建假run、不改active_state；with_students仍原子設定＋新run＋active。與activate競爭仍CAS／409，preview hash／TTL／冪等不變。

欄位限制：`settings_previews.import_id NOT NULL`在`web/src/adapters/sqlite/migrations/0004_settings_versions.sql:14-23`；`idempotency_records.run_id NOT NULL`在`0003_runs_and_calculations.sql:51-57`（不在0004）。SQLite不能以ALTER移除NOT NULL，新增向前migration以**table rebuild**：建新表（欄位可null）→INSERT…SELECT逐列複製→DROP舊表→RENAME→重建索引；settings_previews須含0005新增的`expires_at`（`0005_settings_previews_expires_at.sql:3`）。不能刪DB重建；repository型別與response的runId同步可null。舊資料逐列保留列為必要測試（UX17）。

**8.2.4 空時段與整班移除語意（現況缺陷）**

現況：draftToScheduleOverride對active且sessions為空的班級不寫入override（`settings-repository.ts:174`）；gridRowsToClasses丟掉缺起訖或迄≤起的列（`contracts/settings.ts:136-137`）；resolveClassSessions找不到override就退回seed課表（`web/src/domain/billing/billing-calculator.ts:55-63`）。結果：某班所有列時間清空／刪光，或整班自draft消失時，畫面顯示「待補」（§3.1、§8.1），學生run卻仍用seed舊時段扣天，逐堂、班級、學生三者不同源，違反03 §3 ScheduleVersion「消除空sessions雙義性」。

目標語意，二擇一，**採A**：

- A（採用）：存在已儲存設定版本時，班級與時段的唯一來源是該版本的全量draft（D25），seed只作「尚無任何已儲存設定」的初始值。班級存在但sessions為空＝無時段：不扣天、status=schedule_empty（既有分支`billing-calculator.ts:57-58`），read model對該班回null並列issue，學生run同樣不扣天並帶issue。班級不在該版本＝無此班，落schedule_not_found並列issue。兩者皆不得退回seed。
- B（不採用）：apply拒絕含空時段班級的draft。

理由：(1) D29明定單列時段可刪、整班以active=false軟停用，B會使「刪光時段」或改名散班無法儲存；(2) D25／03已規定draft攜全量以消除空sessions雙義，A是其落實，且與現有active=false→空時段（`settings-repository.ts:170-172`）同語意；(3) B逼使用者為了儲存其他修改而填入假時段，違反D17。確認視窗須列出「N個班級無時段：學生不扣天並列入問題」（§3.2）。

**8.2.5 dirty與同源**

dirty helper涵蓋班級／老師／星期／起迄／停用／班名對應；窗口唯讀不進dirty。計算預覽和提交的draft須完全一致。

### 8.3 查詢與歷史

維持run固定分頁、白名單。**歷史 run 的讀取入口（班級扣天、待設定班級、comparison、`GET /classes?runId=`、班名比對報告的 run 範圍）一律讀該 run 當時的設定快照（`run.scheduleVersionId`），快照缺失＝無法判定，不改用最新設定或 seed 補算（11 D1 已實作；[03 §5.2.2](03-architecture-api.md)，驗收 UX38、UX39）。** 移除UI UNMAPPED_CLASSES固定集合做狀態判斷（`web/src/components/active-run-view.tsx:19,499`），改讀當前resolution／D32動態候選。不能把最新已批准的D30同星期規則退回舊v1。歷史UI只讀，不新增「恢復為現行」寫入功能。
